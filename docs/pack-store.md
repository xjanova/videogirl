# ร้านชุดตัวมายด์ — สัญญาระหว่างแอปกับ xman studio

ชุดใหม่ (ชุดแต่งตัว / เลขาคนใหม่) ทั้งหมดโหลดผ่านหลังบ้าน **xman studio**
เพื่อให้แอดมินเพิ่มชุดและกำหนดราคาได้เอง โดยไม่ต้องออกแอปใหม่

- **ฝั่งแอป** (repo นี้): เรียกแค็ตตาล็อก แสดงราคา โหลดชุดที่ซื้อแล้ว
- **ฝั่งหลังบ้าน** (`D:\Code\xmanstudio`, Laravel): แอดมินเพิ่มชุด ตั้งราคา ดูยอด

---

## 🔴 กฎข้อเดียวที่ห้ามพลาด — URL ของไฟล์ชุดต้องเป็น signed URL

ถ้าลิงก์ `.zip` เป็น URL สาธารณะคงที่ **การจ่ายเงินจะกลายเป็นเรื่องสมัครใจ**
คนแรกที่ซื้อเอาลิงก์ไปแปะที่ไหนก็ได้ แล้วทุกคนโหลดฟรีตลอดกาล
และเราจะไม่มีวันรู้ด้วยซ้ำว่าเกิดขึ้นแล้ว

ทางที่ต้องเป็น: แอปขอ URL ตอนจะโหลด → หลังบ้านเช็คว่า**บัญชีนี้ซื้อแล้วจริง**
→ คืน URL ที่มีลายเซ็นและ**หมดอายุใน 10 นาที**

## Endpoint ที่หลังบ้านต้องมี

### 1. แค็ตตาล็อก (เปิดสาธารณะ)

```
GET /api/packs
```

```json
{
  "packs": [
    {
      "id": "nana-office",
      "name": { "th": "นานา ชุดออฟฟิศ", "en": "Nana — office outfit" },
      "kind": "character",
      "price": 149,
      "currency": "THB",
      "sizeBytes": 36700160,
      "preview": "https://xmanstudio.../previews/nana-office.jpg",
      "requires": null
    }
  ]
}
```

| ช่อง | หมายเหตุ |
|---|---|
| `id` | ต้องตรงกับ `id` ใน `pack.json` ที่อยู่ในไฟล์ zip · ดู [packs.md](packs.md) |
| `kind` | `character` = ตัวละครเต็มตัว · `outfit` = ชุดของตัวละครเดิม |
| `price` | 0 = แจกฟรี |
| `sizeBytes` | แอปเอาไปบอกผู้ใช้ก่อนโหลด · คน 4G ควรได้รู้ว่ากำลังจะโหลด 35MB |
| `requires` | `id` ของชุดตัวละครที่ต้องมีก่อน (สำหรับ `outfit`) · null = ใช้ได้เดี่ยว |

**ไม่ต้องมี `sha256` ตรงนี้** — ใส่ตอนขอลิงก์โหลดพอ เพราะแฮชผูกกับ**ไฟล์**
ไม่ใช่กับ**รายการขาย** และไฟล์อาจถูกอัปเดตโดยที่รายการขายไม่เปลี่ยน

### 2. ของที่บัญชีนี้มี (ต้องมี token)

```
GET /api/packs/mine
Authorization: Bearer <token>
```

```json
{ "owned": ["mind-default", "nana-office"] }
```

คืนแค่รายการ `id` พอ · แอปเอาไปทาบกับแค็ตตาล็อกเอง
แยก endpoint จากแค็ตตาล็อกเพราะแค็ตตาล็อก **แคชได้ยาว** ส่วนสิทธิ์ครอบครอง
เปลี่ยนทันทีที่จ่ายเงินเสร็จ ยัดรวมกันจะแคชไม่ได้ทั้งก้อน

### 3. ขอลิงก์โหลด (ต้องมี token + ต้องซื้อแล้ว)

```
POST /api/packs/{id}/download
Authorization: Bearer <token>
```

```json
{
  "url": "https://.../nana-office.zip?expires=...&signature=...",
  "sha256": "d2f1a4…",
  "expiresIn": 600
}
```

- ยังไม่ได้ซื้อ → **403** (ไม่ใช่ 404 — ต้องแยก "ไม่มีชุดนี้" ออกจาก "มีแต่ยังไม่ได้ซื้อ")
- token หมดอายุ → **401**

`sha256` ที่คืนมา แอปเอาไปตรวจไฟล์ที่โหลดเสร็จเสมอ (มีอยู่แล้วใน `AvatarPacks.install`)

## การจ่ายเงิน — จ่ายบนเว็บ ไม่ใช่ในแอป

แอปเปิดหน้าซื้อของ xman studio ในเบราว์เซอร์ แล้วกลับมากด "รีเฟรช"

**ทำแบบนี้ได้เพราะแอปนี้แจกผ่าน GitHub Releases ไม่ได้อยู่บน Play Store**
กฎ Play billing (ต้องใช้ระบบจ่ายเงินของ Google และโดนหัก 30%) บังคับเฉพาะ
แอปที่อยู่บน Play · **ถ้าวันหนึ่งจะขึ้น Play ต้องกลับมาคิดเรื่องนี้ใหม่ทั้งหมด**
ไม่ใช่แค่ย้ายปุ่ม

ผลพลอยได้: ไม่ต้องฝัง SDK จ่ายเงินในแอป และหลังบ้านมีระบบขายของอยู่แล้ว

## สิทธิ์ครอบครอง — ใช้ระบบไลเซนส์ที่ xman studio มีอยู่แล้ว

เจ้าของสั่งให้ดูของเดิม (TpingApp / WinXTools) แล้วทำตาม · **มีอยู่แล้วจริง
และเคยยืนยันกับเซิร์ฟเวอร์สดแล้ว** ไม่ต้องคิดระบบใหม่

**Base:** `https://xman4289.com/api/v1/license` (Laravel)
เช็คสุขภาพ `GET /api/health` → `{status:healthy, api_version:v1}`

**Routes (POST):** `/activate` · `/validate` · `/deactivate` · `/demo`

> ⚠️ path แบบ `/api/v1/products/{slug}/*` ที่เคยเขียนไว้ในเอกสารเก่า **ผิด**
> ยิงจริงได้ 404 · และ `/register-device` **ไม่มี** อย่าเรียก

**ฟิลด์ที่เซิร์ฟเวอร์บังคับ (ขาดแล้ว 422):**
- `/validate` ต้องมี `machine_id` + `license_key`
- `/activate` และ `/demo` ต้องมี `machine_fingerprint`
- → ส่ง **ทั้งสองตัว** (ค่าแฮชเดียวกัน) พร้อม `product` · `device_name` · `app_version`
- ต้องมี header `Accept: application/json` ไม่งั้น Laravel อาจตอบเป็น HTML

**ผลลัพธ์สำเร็จ:** `{success:true, data:{type, expires_at, days_remaining, …}}`
`type` ∈ `lifetime` `yearly` `monthly` `weekly` `daily` `demo` `free`

**แบบที่ TpingApp ทำ (แอป Android เหมือนกัน — ลอกได้เลย):**
- สแกน **QR** เพื่อ activate ไม่ต้องพิมพ์คีย์ยาว ๆ บนมือถือ
- **HWID auto-check** — ลงใหม่บนเครื่องเดิม activate ให้เองไม่ต้องกรอกซ้ำ

**เก็บสถานะล่าสุดไว้เสมอ แล้วใช้ตอนเน็ตล่ม (offline grace)** — ไม่งั้นเน็ตหลุด
= ชุดที่ซื้อแล้วใช้ไม่ได้ ซึ่งผู้ใช้อ่านว่า "แอปยึดของที่จ่ายเงินไปแล้ว"

**ตอบคำถามย้ายเครื่อง:** ผูก HWID + มี `/deactivate` = ย้ายเครื่องได้
แต่ต้องปลดจากเครื่องเดิมก่อน

### machine id บน Android ต่างจากบน Windows

สูตรเดิมเป็น `SHA-256(MachineName:UserName:ProcessorCount)` ซึ่งเป็นของ .NET
บน Android ไม่มีสามค่านั้น · ต้องเลือกฐานใหม่ที่**คงที่ตลอดอายุการติดตั้ง**
และ **ไม่ใช่ตัวระบุถาวรของเครื่อง** (Google ห้ามใช้ IMEI/serial แล้ว)
→ `Settings.Secure.ANDROID_ID` เป็นตัวที่เหมาะที่สุด
⚠️ มันเปลี่ยนเมื่อ factory reset และต่างกันต่อแอปต่อผู้ใช้ — ซึ่งยอมรับได้
แต่ต้องบอกผู้ใช้ว่า reset เครื่องแล้วต้อง activate ใหม่

## ที่ยังต้องตัดสินใจก่อนเขียนฝั่ง Laravel

1. **ไฟล์ zip เก็บที่ไหน** — R2 / storage ของ xmanstudio เอง · มีผลกับวิธีเซ็น URL
2. **หนึ่งไลเซนส์ = ทุกชุด หรือ ไลเซนส์ต่อชุด** — ของเดิมเป็นไลเซนส์ต่อผลิตภัณฑ์
   ถ้าจะขายทีละชุด ต้องเพิ่มชั้น `owned[]` ตามที่เขียนไว้ข้างบน
3. **คืนเงิน/ถอนชุด** — ถ้าถอนสิทธิ์ แอปควรลบชุดที่โหลดไปแล้วไหม
