## ค้นเว็บ (`/v1/responses`)

- ลองตามลำดับ: รุ่นที่ผ่านล่าสุด → สมองที่เลือก → `gpt-6-luna` → `gpt-6-astra`
  (`MindState.webSearchModels`)
- 🔴 `gpt-4.1-mini` ไม่ใช่สาย reasoning แต่ตัวแทนใช่ · รุ่น reasoning ต้องส่ง
  `reasoning: {effort: low}` (`OpenAiClient.webSearch`) · ไม่ส่ง = medium กินเพดาน
  `max_output_tokens` เดียวกับคำตอบ · `none` ของ `effortFor` เป็นของงานคุยเท่านั้น

## เสียงพูด (Realtime แบบครั้งเดียวจบ)

- **`/v1/audio/speech` ไม่เหลือรุ่นหลัง 2027-01-06** · ตัวแทนที่ประกาศคือ
  `gpt-realtime-2.1-mini` ซึ่ง**เรียกได้ทาง Realtime เท่านั้น** (เอกสารเขียนชัดว่าไม่รองรับ speech)
  จึงเปลี่ยนท่อ ไม่ใช่เปลี่ยนชื่อรุ่น
- `lib/ai/realtime_speech.dart`: หนึ่งข้อความ = เปิด WebSocket หนึ่งเซสชัน · `session.update` →
  รอ `session.updated` → `response.create` แบบ `conversation: none` ข้อความอยู่ใน `input` →
  เก็บ `response.output_audio.delta` → ห่อ PCM 24 kHz เป็น WAV (`audio/wav`)
- 🔴 รุ่นนี้เป็นโมเดลคุย ไม่ใช่เครื่องอ่าน · กันด้วยคำสั่งห้ามตอบ และข้อความไปเป็นข้อความผู้ใช้
  ไม่ใช่ `instructions` · เอกสาร OpenAI ไม่รับประกันว่าอ่านตรงตัวอักษร
- เสียง: marin, cedar (OpenAI แนะนำว่าดีที่สุด), coral, shimmer, sage, ballad
- `fable` `nova` `onyx` ไม่มีใน Realtime · ค่าที่บันทึกไว้เปลี่ยนเป็น marin พร้อมบอกเจ้าของ ·
  พิมพ์ชื่อเสียงอื่นเองที่ Realtime ไม่รู้จัก = ขึ้น `errVoiceNotRealtime` ตอนใช้
- ช้ากว่าเดิมเล็กน้อยต่อประโยค (ต้องเปิดท่อใหม่ทุกครั้ง) · คิดเงินเป็น token ของ Realtime
  (เสียงขาออก $20 ต่อล้าน token · ข้อความขาเข้า $0.6 · ตรวจ 2026-11-02) ไม่ใช่ราคาต่อนาทีแบบ TTS

### ล้มแล้วเกิดอะไร

- `MindState.synthesizeWithFallback` ตกไปเสียงเครื่องพร้อมขึ้น `S.voiceFellBack(เหตุผล)`
  ซึ่งบอกทั้งเหตุผลและว่าตอนนี้ฟังเสียงเครื่องอยู่ · ใช้กับทุกเจ้าเสียง ไม่ใช่แค่ OpenAI
- ลองฟังในหน้าตั้งค่าไม่ตกไปเสียงเครื่องเลย (`previewVoice`)
- ทุกทางล้มใน `RealtimeSpeech` ต้องเป็น `OpenAiFailure` · ผู้เรียกจับชนิดนี้ชนิดเดียว
- ไม่แสดงข้อความดิบของเซิร์ฟเวอร์ Realtime ขึ้นจอ (อาจมีคีย์แบบบังบางส่วน) · แสดงเฉพาะรหัส

## ถอดเสียง

### ไฟล์ (`/v1/audio/transcriptions`)

- รุ่นหลัก `gpt-transcribe` · ใช้ `languages[]` แทน `language` (ส่งทั้งคู่ไม่ได้) ·
  ไม่ส่ง `response_format` · คำตอบเป็น JSON `{text, languages}`
- บันได (`OpenAiConfig.sttLadder`): `gpt-transcribe` + `th` → `whisper-1` + `th` →
  `gpt-transcribe` เดาภาษาเอง · ขั้นที่ผ่านถูกจำไว้จนปิดแอป และบอกเจ้าของครั้งเดียว
  (`S.sttFellBack`) · หมดบันได = `S.errSttRetired`
- 🔴 ตกขั้นเฉพาะเมื่อ OpenAI ไม่รับ**รุ่นหรือภาษา** (403 · 404 · 400 ที่พูดถึง language/model) ·
  400 เรื่องไฟล์ (เสียงสั้นเกิน) ต้องไม่นับ ไม่งั้นคำสั้นคำเดียวทำให้ตกขั้นทั้งเซสชัน
- พร็อกซีของเรากับเซิร์ฟเวอร์ในบ้านยังส่ง `whisper-1` + `language` · ปลายทางพวกนั้นเลียนแบบ API
  ของ whisper-1 · ⚠️ พร็อกซีอยู่นอก repo นี้ ถ้าหลังบ้านส่งต่อ `whisper-1` ตรง ๆ ไป OpenAI
  ต้องย้ายฝั่งเซิร์ฟเวอร์ก่อน 2027-02-26

### ในเซสชัน Realtime (`audio.input.transcription`)

- รุ่นหลัก `gpt-transcribe` + `languages` · บันไดเหมือนกันแต่ขั้นกลางคือ `gpt-4o-mini-transcribe`
- ใช้ `gpt-live-transcribe` ไม่ได้ · เอกสารบอกว่าไม่รองรับ `server_vad` / `semantic_vad`
  ซึ่งเซสชันในสายและแชทใช้อยู่
- 🔴 `session.update` ที่ถูกปฏิเสธ = เซสชันไม่มี prompt ของสาย ไม่มีเครื่องมือ และเสียงเปลี่ยนไม่ได้
  หลังคำแรก · คำทักจึงรอ `session.updated` (ไม่เกิน `RealtimeCall.configLimit` 1.5 วิ) ·
  ถูกปฏิเสธ = ลองขั้นถัดไป · หมดบันได = ปิดท่อให้ผู้เรียกตกไปทางเดิม

## Realtime

- สายและแชทด้วยเสียงใช้ `gpt-realtime-2.1` (`RealtimeCall.defaultModel`) · **ไม่อยู่ในรายการปิด**
  (รายการปิด 2027-01-20 คือ `gpt-realtime` ไม่มีเลขรุ่น) · GPT-Live ใช้ `gpt-live-1` + หลังบ้าน `gpt-6-luna`

## สิ่งที่ยังยืนยันจากเอกสารไม่ได้ · ต้องลองกับ API จริง

เทสต์ใช้เซิร์ฟเวอร์ปลอมทั้งหมด (2026-11-02 ไม่มีคีย์ในเครื่องที่พัฒนา) จึงยังไม่เคยยิงของจริง:

- `gpt-transcribe` รับ `th` ไหม · เอกสารบอกว่ารับรหัส ISO 639-1 แต่ไม่ได้ให้รายการครบ และไม่พูดถึงภาษาไทย
- `gpt-transcribe` ใน `session.update` แบบ `type: realtime` รับ `prompt` และ `languages` จริงไหม
- `gpt-realtime-2.1-mini` อ่านภาษาไทยตรงตัวไหม (โดยเฉพาะประโยคคำถาม ซึ่งเสี่ยงที่จะตอบแทนอ่าน)
- `gpt-6-luna` ค้นเว็บด้วย `reasoning: low` ได้ผลดีแค่ไหน
- คุณภาพภาษาไทยของทุกรุ่น (เอกสารไม่พูดถึง)
