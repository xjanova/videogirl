# รับสายแทน — ทำได้แค่ไหน และติดตรงไหน

หน้านี้เป็นความจริงล่าสุดของฟีเจอร์ "เธอรับสายแทน" · ถ้าโค้ดกับหน้านี้ขัดกัน
ให้เชื่อโค้ด แล้วมาแก้หน้านี้

## สรุปสั้น

### ถอดเสียงคู่สายด้วยสมองในเครื่อง (2026-10-05)

ของเดิมสายที่ใช้สมองในเครื่อง (ค่าตั้งต้น) หูดับตั้งแต่ประโยคแรก เพราะ
`transcribeCall` ส่งต่อไป `transcribeChat` ที่โยนข้อผิดพลาดทันที (สัญญาว่า
เสียงไม่ออกนอกเครื่อง) · ตอนนี้แอป (ที่เป็นแอปโทรศัพท์หลัก จึงอัดได้) ป้อนไฟล์
ที่อัดแล้วให้ `createOnDeviceSpeechRecognizer` ผ่าน `EXTRA_AUDIO_SOURCE`
— ตัวถอดเสียงไม่ต้องแย่งไมค์กับสายเอง ซึ่งระบบไม่ยอมอยู่แล้ว

⚠️ **ยังไม่ได้ลองบนเครื่องจริง** · ถ้าตัวถอดเสียงของเครื่องไม่รับเสียงจากท่อ
มันจะไปเปิดไมค์เอง (ตามเอกสารของ Android) ซึ่งระหว่างสายน่าจะได้ความเงียบ
→ ได้ `noMatch` → รอบเงียบ → ครบสามรอบเธอเลิกฟัง แล้วเหลือทางพิมพ์

### รับฝากเรื่อง

สายที่เธอเป็นคนคุย พอวางสาย → สรุปด้วยสมองตัวที่เลือก ("ใครโทรมา เรื่องอะไร
ฝากอะไร ต้องโทรกลับไหม" · สั่งห้ามเติมเบอร์/เวลาที่ไม่ได้ถูกพูด) → เก็บสรุป
+ บทสนทนาเต็มในตาราง `call_notes` → ลงไทม์ไลน์ (แตะเปิดอ่านได้) → แจ้งเตือน
ช่อง `call_notes` · สรุปไม่ได้ก็ยังเก็บคำที่คู่สายพูดไว้
· เธอรู้เรื่องที่ฝากไว้ (สองวันล่าสุด) ตอนเจ้าของถาม แต่ **prompt ตอนรับสาย
ไม่มีเรื่องที่คนอื่นฝากไว้** — คู่สายคือคนแปลกหน้าที่พิมพ์เข้า prompt ได้

## รับสายตอนแอปไม่ได้อยู่บนจอ (2026-10-06)

การคุยในสายต้องมี Dart ของแอปทำงานอยู่ (สมอง เสียง บทสนทนาอยู่ในนั้นทั้งหมด) ·
จอสายเนทีฟ (`InCallActivity`) ขึ้นได้เสมอเพราะเป็นแอปโทรศัพท์หลัก แต่ถ้าไม่มี Dart
และเครื่องล็อกอยู่ **เธอจะไม่รับเอง** (`dartAlive`) — ไม่มีใครคุยกับคนโทรมา

| สถานะแอป | เธอรับสาย/คุยได้ไหม |
|---|---|
| เปิดอยู่บนจอ | ✅ |
| กดย้อนกลับ/Home (พักไว้เบื้องหลัง) | ✅ — ปุ่มย้อนกลับ**ไม่ปิดแอป**แล้ว (`AppLife.moveToBack`) |
| อยู่เบื้องหลังนาน ระบบปิดแอปเอง | ❌ — เปิด "เฝ้างาน" (บริการเบื้องหน้า) ให้ถูกปิดยากขึ้น |
| กดปุ่ม "ออกจากแอป" | ❌ — ตั้งใจ: คืนหน่วยความจำทั้งหมด |

ยังไม่ได้ทำ: ปลุกแอปขึ้นมาคุยเองจากจอสายตอนที่แอปปิดสนิท (ต้องสร้าง FlutterEngine
เบื้องหลัง + โหลดสมองให้ทันระหว่างกริ่งดัง ซึ่งสมองในเครื่องโหลดหลายวินาที)

## 🔴 เพดานที่ทุกอย่างตั้งอยู่บน

ตั้งแต่ **Android 10 (API 29)** `VOICE_CALL` / `VOICE_UPLINK` / `VOICE_DOWNLINK`
สงวนไว้ให้แอประบบและแอปของผู้ให้บริการเครือข่ายเท่านั้น
**การเป็นแอปโทรศัพท์หลักไม่ได้ให้สิทธิ์พวกนี้** และไม่มี API อื่นที่ทดแทน

ดังนั้นทั้งขาเข้าและขาออกของเสียงในสาย เราแตะไม่ได้เลย
สิ่งที่ทำอยู่ตอนนี้จึงเป็นกลไก **อะคูสติก** ไม่ใช่การต่อสายสัญญาณ

## เธอ → ปลายสาย (ทำงานได้ ถ้าเครื่องยอม)

```
TTS → ไฟล์เสียง → MediaPlayer เล่นออกลำโพง → คลื่นในอากาศ → ไมค์ของเครื่อง → ขึ้นสาย
```

ทำใน `CallAudio.kt`:
1. `InCallService.setAudioRoute(ROUTE_SPEAKER)` — บังคับเปิดลำโพง
   (ทำได้เฉพาะตอนเป็นแอปโทรศัพท์หลัก ไม่งั้น `open()` คืน false)
2. เร่งระดับเสียงของช่องที่ใช้ขึ้นสุด แล้ว **คืนค่าเดิมเมื่อสายจบเสมอ**
3. `MediaPlayer` ที่ตั้ง `USAGE_VOICE_COMMUNICATION` (หรือ `USAGE_MEDIA`)

**ตัวแปรที่ตัดสินว่าได้ยินหรือไม่ได้ยินคือ AEC ของเครื่อง**
ตัวตัดเสียงก้องมีหน้าที่ลบสิ่งที่ลำโพงเล่นออกจากสัญญาณไมค์พอดี ๆ
ซึ่งคือสิ่งที่เรากำลังทำ · บางชิปอ้างอิงเฉพาะเสียงขาลงของสาย (เสียงเธอรอด)
บางชิปอ้างอิงเสียงลำโพงทั้งหมด (เสียงเธอโดนลบ)
**อ่านจากโค้ดไม่ได้ ต้องลองกับเครื่องจริง**

จึงมีสวิตช์ **"ทางที่เสียงเธอวิ่งเข้าสาย"** ในหน้าตั้งค่า (ช่องเสียงสาย /
ช่องเสียงสื่อ) ให้เจ้าของลองสลับเมื่อปลายสายไม่ได้ยิน
ค่านี้เก็บที่คีย์ `callStream` ซึ่ง **ฝั่ง Kotlin อ่านเองด้วย** (`MindPrefs`)

### ลำโพงต้องเปิดค้างทั้งสาย (2026-10-06)

เจ้าของ: "ปลายสายหรือคนโทร ไม่ได้ยินเสียงน้องมาย" · ของเดิมสั่งลำโพง**ครั้งเดียว**
ใน `mindAnswer` ซึ่งสายเข้าคือตอน**กริ่งยังดัง** (`answer()` ยังไม่เสร็จ) · หลายเครื่อง
ตั้งเส้นทางใหม่เป็นหูฟังตอนสายต่อติด แล้วไม่มีใครเปิดคืน → เสียงเธอออกหูฟังเบา ๆ
ไมค์ไม่ได้ยิน ไม่มี error อะไรเลย

- `CallAudio.keepSpeaker` เรียกตอนสายที่เธอถือต่อติด (+ เช็กซ้ำ 0.8 / 2.5 วิ) และทุกครั้ง
  ที่ `onCallAudioStateChanged` · ไม่ใช่ลำโพง (หูฟัง/บลูทูธ/หูฟังสาย) = เปิดคืน · ไมค์สาย
  ถูกปิด = เปิดคืน · ไม่เกิน 8 ครั้งต่อสาย · เร่งระดับเสียงซ้ำเมื่อลำโพงติดจริง (ระดับเสียงสาย
  แยกตามอุปกรณ์) · ช่องสื่อเร่งช่องสายด้วย (ระบบกดเสียงสื่อไม่ให้ดังเกินเสียงสายระหว่างสาย)
- เจ้าของ**ปิด**ลำโพงเองบนจอสาย (`CallAudio.ownerRouted`) = ไม่เปิดทับ · แทรกสาย = เลิกเฝ้า
- Dart รอลำโพงติดจริงก่อนคำแรก (`_awaitSpeaker` ไม่เกิน 3 วิ) · ลำโพงปิดเกิน 3 วิระหว่างที่เธอ
  ถือสาย = คำเตือนบนแผงสาย แตะแล้วเปิดคืน (`callSpeakerOn`)
- ไมค์ของทั้งสายไม่ขอ audio focus แล้ว (`audioInterruption: none`)
- รายงาน: `echo` = เสียงเธอดังแค่ไหนในห้องตอนพูด (ไมค์ของเราเอง ไม่ผ่าน AEC ของสาย) ·
  `spkLost` = เคยเห็นลำโพงปิด · **echo ต่ำ** = เสียงไม่ออกลำโพง (เส้นทาง/ระดับเสียง) ·
  **echo สูงแต่ปลายสายไม่ได้ยิน** = AEC ของเครื่องลบทิ้ง → สลับช่องเสียง ·
  เจ้าของเช็กเองได้: เปิดฟังไฟล์บันทึกสาย ถ้าได้ยินเสียงเธอดังชัด แปลว่าลำโพงทำงาน

## ปลายสาย → เธอ — ต้องเปิดบริการการช่วยเหลือพิเศษ (2026-10-06)

ยืนยันจากเอกสาร Android (sharing-audio-input): ระหว่างมีสาย (`MODE_IN_CALL`)
แอปทั่วไปที่อัดเสียงได้**ความเงียบ** · ข้อยกเว้นมีแค่แอประบบที่ถือ
`CAPTURE_AUDIO_OUTPUT` กับ **แอปที่เป็นบริการการช่วยเหลือพิเศษ** · การเป็นแอปโทรศัพท์หลัก
ไม่ช่วย · เจ้าของเจอจริง: "รับแล้ว แต่ไม่ยอมพูดตอบโต้อะไรเลย"

- `MindAccessibility` ไม่อ่านหน้าจอ ไม่กดอะไร · มีไว้ให้ระบบยอมให้อัดระหว่างสาย
- แอปที่ไม่ได้ลงจาก Play ต้อง "อนุญาตการตั้งค่าที่ถูกจำกัด" ก่อน (เหมือนบทบาทแอปโทรศัพท์)
- ไมค์เปิดค้างทั้งสาย (ไม่เปิด-ปิดทุกเทิร์น) · ตอนเธอพูดแค่ไม่ฟัง · ได้เสียงต่อเนื่องไว้บันทึก
- สายที่หูหนวก/ปลายสายไม่ได้ยิน/ไม่ได้ยินใครเลย → `noteIncident` → รายงานส่งเอง
  (`call: rounds heard peak deaf mute a11y stream`)

### ทั้งสองทางเงียบ — จอต้องติดค้าง และรู้ให้ได้ว่าระบบปิดไมค์ (2026-10-07)

เจ้าของ: "คนที่โทรมาไม่ได้ยินเสียงที่มายด์พูดเลย และมายด์ก็ไม่ได้ยินเสียงที่พูดมาเลย ·
เป็นเพราะเปิดลำโพงให้ดังหรือเปล่า"

**ลำโพงไม่ใช่ต้นเหตุ และปิดไม่ได้** — ลำโพงคือทางเดียวที่เสียงวิ่งได้ทั้งสองทาง (เสียงเธอ
ออกลำโพง → ไมค์ของสาย · เสียงคู่สายออกลำโพง → ไมค์ของเธอ) · ปิดลำโพง = เสียงออกหูฟังเบา ๆ
ที่ไมค์ไม่ได้ยินเลยทั้งสองทาง · ความดังสุดก็ไม่ได้ทำให้ไมค์ของเธอได้ยินน้อยลง

กฎจริงจากโค้ด AOSP (`AudioPolicyService::updateUidStates_l`, Android 14) — ระหว่าง
`MODE_IN_CALL` แอปที่เป็นบริการการช่วยเหลือพิเศษอัดได้ **เฉพาะ** แหล่ง `VOICE_RECOGNITION`
**และ** ตอนแอปอยู่สถานะบนสุด · บวกสิทธิ์ไมค์แบบ "ระหว่างใช้งาน" ที่ต้องมีจอของแอปอยู่บนสุดจริง
(บริการที่ระบบโทรศัพท์ผูกไว้ไม่ได้สิทธิ์ไมค์) · ไม่ครบ = ระบบส่งศูนย์ล้วนให้ ไม่มี error

- **จอดับกลางสาย = เธอหูดับ** · ลำโพงเปิดไม่มีอะไรแตะจอ จอดับตามเวลาพักจอ · ของเดิมติดจอ
  ค้างเฉพาะ Android ต่ำกว่า 8.1 → `CallScreen` ติดจอค้าง (decorView `keepScreenOn` ไม่ชน
  ธงของสตูดิโอ) ทั้งจอสายเนทีฟและจอเธอ ตลอดที่ `MindInCallService.mindLive()` · ปล่อยเมื่อ
  สายจบ/เจ้าของแทรกสาย
- **จอสายไม่ขอปลดล็อกแล้ว** (`requestDismissKeyguard`) · เครื่องล็อกด้วย PIN แป้นกรอกรหัส
  เด้งบังจอสายตั้งแต่กริ่งดัง จอที่ถูกบังไม่นับเป็นจอที่ขอติดค้าง แล้วหมดเวลาจอดับ ·
  ขึ้นทับจอล็อก (`setShowWhenLocked`) พอสำหรับรับ/วางสาย
- **รู้ได้ตรง ๆ ว่าระบบปิดไมค์** · `CallAudio.micSilenced` ถาม
  `AudioRecordingConfiguration.isClientSilenced` (Android 10+) ของการอัดแบบ
  `VOICE_RECOGNITION` 16 kHz ส่งมากับ `callInfo` ทุกวินาที → `CallSession.micBlocked`
  (เกินสองวิ) → แผงสายเตือน "ระบบของเครื่องกำลังปิดไมค์ของเธอ" แทนคำเดาว่าหูหนวก ·
  รายงานได้ `silenced=` · ไม่ตั้ง `deaf` ให้ (ปิดชั่วคราวต้องฟังต่อได้เอง)

อ่านรายงานสายครั้งถัดไป:

| `silenced` | `peak` | `echo` | แปลว่า |
|---|---|---|---|
| true | ~0 | ~0 | ระบบปิดไมค์ของเธอ · ดู a11y และจอดับ/สลับแอประหว่างสาย |
| false | ~0 | ~0 | ROM ส่งศูนย์เองโดยไม่ผ่านกฎข้างบน · เครื่องนี้ไม่ให้ฟังสาย |
| false | สูง | สูง | ไมค์เธอได้ยินทั้งคู่สายและตัวเธอ · ถ้าปลายสายยังไม่ได้ยินเธอ = AEC ของเครื่องลบเสียงเธอ → สลับช่องเสียง · ไม่ได้ผลก็เหลือทางรับสายฝั่งเซิร์ฟเวอร์ |
| false | สูง | ต่ำ | เสียงเธอไม่ออกลำโพง (เส้นทาง/ระดับเสียง) |

## คุยสด — OpenAI Realtime (2026-10-06)

สมอง OpenAI ด้วยคีย์ของเจ้าของ + สวิตช์ "คุยสดแบบ Realtime" (เปิดเป็นค่าตั้งต้น) →
`realtime_call.dart`: WebSocket `wss://api.openai.com/v1/realtime?model=gpt-realtime-2.1`
· ไมค์ 16 kHz แปลงเป็น 24 kHz ส่งต่อเนื่อง · เซิร์ฟเวอร์จับจังหวะพูด (server_vad 600 ms)
แล้วตอบเป็นเสียง PCM 24 kHz ทีละชิ้น → `CallAudio.liveStart/liveWrite` (AudioTrack สตรีม)
· บทของทั้งสองฝั่งมาจากการถอดเสียงของเซสชันเอง → บันทึกสาย

- **พูดทีละฝั่ง:** ไมค์ไม่เข้าเซสชันตอนเสียงเธอยังออกลำโพง (+250 ms) · ลำโพง/ไมค์เดียวกัน
  ไม่กั้น = เธอได้ยินตัวเองแล้วตอบตัวเอง · คู่สายแทรกกลางประโยคเธอไม่ได้
- ปากบนเวทีใช้โหมดพึมพำ (ไม่มีไฟล์ทั้งประโยคให้อ่านคลื่น)
- ต่อไม่ได้ = ทางเดิมตั้งแต่ทัก · หลุดกลางสาย = ทางเดิมต่อ (ไม่ทักซ้ำ)

## ปลายสาย → เธอ (กลไก)

```
เสียงคู่สายออกลำโพง → ไมค์ → AudioRecord (voiceRecognition) → VAD → whisper-1 → ข้อความ
```

หลายเครื่อง **คืนความเงียบสนิท** ให้แอปที่อัดเสียงระหว่างมีสาย
โดยไม่มี error ไม่มี permission denied — ได้ก้อนข้อมูลครบ ขนาดถูกต้อง
แต่ทุกตัวอย่างเป็นศูนย์

จับได้ทางเดียวคือ **วัดระดับเสียงที่อัดได้จริง** ซึ่งเป็นสิ่งที่
`CallSession.micLevel` ทำ และหน้าจอสายแสดงเป็นแถบเล็ก ๆ ข้างสถานะ
เงียบสนิทติดกันสามรอบ → `deaf = true` → เลิกอัด เลิกจ่ายค่าถอดเสียง
แล้วบอกเจ้าของตรง ๆ ว่าเครื่องนี้ไม่ให้ฟัง

**เมื่อหูหนวก ฟีเจอร์ยังทำงานได้ครึ่งหนึ่ง** — ช่องพิมพ์บนหน้าจอสาย
ส่งข้อความให้เธอพูดเข้าสายได้ตามปกติ เพราะทางนั้นไม่ต้องใช้ไมค์เลย

## ทางที่ไม่ต้องลุ้นเลย — รับสายฝั่งเซิร์ฟเวอร์

```
คนโทรเข้า → เบอร์ Twilio/VoIP → เซิร์ฟเวอร์เรา ↔ OpenAI Realtime
                                        ↓
                                   แอปแสดง transcript สด + แทรกสายได้
```

- **หน้าจอสายที่ทำไว้แล้วใช้ต่อได้ทั้งหมด** เปลี่ยนแค่ว่าเสียงวิ่งทางไหน
- คุณภาพเสียงดีกว่ามาก เพราะเป็นสายเสียงตรง ไม่ผ่านอากาศ
- ดีเลย์ต่ำกว่า เพราะไม่ต้องรอ TTS แล้วค่อยเล่น
- ไม่มีเรื่อง AEC ไม่มีเรื่องเครื่องไม่ให้อัด — ไม่ขึ้นกับรุ่นเครื่องเลย

ข้อแลกเปลี่ยน: มีค่าเบอร์รายเดือน + ค่านาที และต้องตั้ง forward สายจากเบอร์เดิม
ไปเบอร์ใหม่ (หรือประกาศเบอร์ใหม่ให้คนที่จะโทรหา)

## สิทธิ์ที่ต้องมี

- `READ_PHONE_STATE` + `READ_CALL_LOG` — คู่กันเสมอ ไม่งั้นเบอร์ว่างเปล่าเงียบ ๆ
- `READ_CONTACTS` — เบอร์กลายเป็นคน และเป็นตัวกรองของ auto-answer
- `ANSWER_PHONE_CALLS` — รับสาย
- `RECORD_AUDIO` — ฟังปลายสาย
- `MODIFY_AUDIO_SETTINGS` — เร่ง/คืนระดับเสียงของช่องสาย (ระบบให้ตอนติดตั้ง)
- `CALL_PHONE` — โทรออกจากแป้นของเราเอง
- บทบาท **แอปโทรศัพท์หลัก** — ผู้ใช้ต้องกดเลือกเอง ถอนได้ตลอด

🔴 เป็นแอปหลักแล้ว **ทุกสายของเครื่องผ่านแอปนี้** จอสายหรือแป้นโทรพังเมื่อไหร่
เจ้าของโทรออกรับสายไม่ได้ทั้งเครื่อง ไม่ใช่แค่ฟีเจอร์นี้เสีย
