# รับสายแทน — ทำได้แค่ไหน และติดตรงไหน

หน้านี้เป็นความจริงล่าสุดของฟีเจอร์ "เธอรับสายแทน" · ถ้าโค้ดกับหน้านี้ขัดกัน
ให้เชื่อโค้ด แล้วมาแก้หน้านี้

## สรุปสั้น

| อยากได้ | ทำได้ไหม | ทำที่ไหน |

| ปากเธอบนจอขยับตามคำที่พูดเข้าสาย | ✅ | `MindLips` — ดู [studio.md](studio.md) |

### ถอดเสียงคู่สายด้วยสมองในเครื่อง (2026-10-05)

ของเดิมสายที่ใช้สมองในเครื่อง (ค่าตั้งต้น) หูดับตั้งแต่ประโยคแรก เพราะ
`transcribeCall` ส่งต่อไป `transcribeChat` ที่โยนข้อผิดพลาดทันที (สัญญาว่า
เสียงไม่ออกนอกเครื่อง) · ตอนนี้แอป (ที่เป็นแอปโทรศัพท์หลัก จึงอัดได้) ป้อนไฟล์
ที่อัดแล้วให้ `createOnDeviceSpeechRecognizer` ผ่าน `EXTRA_AUDIO_SOURCE`
— ตัวถอดเสียงไม่ต้องแย่งไมค์กับสายเอง ซึ่งระบบไม่ยอมอยู่แล้ว

⚠️ **ยังไม่ได้ลองบนเครื่องจริง** · ถ้าตัวถอดเสียงของเครื่องไม่รับเสียงจากท่อ
มันจะไปเปิดไมค์เอง (ตามเอกสารของ Android) ซึ่งระหว่างสายน่าจะได้ความเงียบ
→ ได้ `noMatch` → รอบเงียบ → ครบสามรอบเธอเลิกฟัง แล้วเหลือทางพิมพ์

### รับฝากเรื่อง

สายที่เธอเป็นคนคุย พอวางสาย → สรุปด้วยสมองตัวที่เลือก ("ใครโทรมา เรื่องอะไร
ฝากอะไร ต้องโทรกลับไหม" · สั่งห้ามเติมเบอร์/เวลาที่ไม่ได้ถูกพูด) → เก็บสรุป
+ บทสนทนาเต็มในตาราง `call_notes` → ลงไทม์ไลน์ (แตะเปิดอ่านได้) → แจ้งเตือน
ช่อง `call_notes` · สรุปไม่ได้ก็ยังเก็บคำที่คู่สายพูดไว้
· เธอรู้เรื่องที่ฝากไว้ (สองวันล่าสุด) ตอนเจ้าของถาม แต่ **prompt ตอนรับสาย
ไม่มีเรื่องที่คนอื่นฝากไว้** — คู่สายคือคนแปลกหน้าที่พิมพ์เข้า prompt ได้

## รับสายตอนแอปไม่ได้อยู่บนจอ (2026-10-06)

การคุยในสายต้องมี Dart ของแอปทำงานอยู่ (สมอง เสียง บทสนทนาอยู่ในนั้นทั้งหมด) ·
จอสายเนทีฟ (`InCallActivity`) ขึ้นได้เสมอเพราะเป็นแอปโทรศัพท์หลัก แต่ถ้าไม่มี Dart
และเครื่องล็อกอยู่ **เธอจะไม่รับเอง** (`dartAlive`) — ไม่มีใครคุยกับคนโทรมา

| สถานะแอป | เธอรับสาย/คุยได้ไหม |
|---|---|
| เปิดอยู่บนจอ | ✅ |
| กดย้อนกลับ/Home (พักไว้เบื้องหลัง) | ✅ — ปุ่มย้อนกลับ**ไม่ปิดแอป**แล้ว (`AppLife.moveToBack`) |
| อยู่เบื้องหลังนาน ระบบปิดแอปเอง | ❌ — เปิด "เฝ้างาน" (บริการเบื้องหน้า) ให้ถูกปิดยากขึ้น |
| กดปุ่ม "ออกจากแอป" | ❌ — ตั้งใจ: คืนหน่วยความจำทั้งหมด |

ยังไม่ได้ทำ: ปลุกแอปขึ้นมาคุยเองจากจอสายตอนที่แอปปิดสนิท (ต้องสร้าง FlutterEngine
เบื้องหลัง + โหลดสมองให้ทันระหว่างกริ่งดัง ซึ่งสมองในเครื่องโหลดหลายวินาที)

## 🔴 เพดานที่ทุกอย่างตั้งอยู่บน

ตั้งแต่ **Android 10 (API 29)** `VOICE_CALL` / `VOICE_UPLINK` / `VOICE_DOWNLINK`
สงวนไว้ให้แอประบบและแอปของผู้ให้บริการเครือข่ายเท่านั้น
**การเป็นแอปโทรศัพท์หลักไม่ได้ให้สิทธิ์พวกนี้** และไม่มี API อื่นที่ทดแทน

ดังนั้นทั้งขาเข้าและขาออกของเสียงในสาย เราแตะไม่ได้เลย
สิ่งที่ทำอยู่ตอนนี้จึงเป็นกลไก **อะคูสติก** ไม่ใช่การต่อสายสัญญาณ

## เธอ → ปลายสาย (ทำงานได้ ถ้าเครื่องยอม)

```
TTS → ไฟล์เสียง → MediaPlayer เล่นออกลำโพง → คลื่นในอากาศ → ไมค์ของเครื่อง → ขึ้นสาย
```

ทำใน `CallAudio.kt`:
1. `InCallService.setAudioRoute(ROUTE_SPEAKER)` — บังคับเปิดลำโพง
   (ทำได้เฉพาะตอนเป็นแอปโทรศัพท์หลัก ไม่งั้น `open()` คืน false)
2. เร่งระดับเสียงของช่องที่ใช้ขึ้นสุด แล้ว **คืนค่าเดิมเมื่อสายจบเสมอ**
3. `MediaPlayer` ที่ตั้ง `USAGE_VOICE_COMMUNICATION`

**ตัวแปรที่ตัดสินว่าได้ยินหรือไม่ได้ยินคือ AEC ของเครื่อง**
ตัวตัดเสียงก้องมีหน้าที่ลบสิ่งที่ลำโพงเล่นออกจากสัญญาณไมค์พอดี ๆ
ซึ่งคือสิ่งที่เรากำลังทำ · บางชิปอ้างอิงเฉพาะเสียงขาลงของสาย (เสียงเธอรอด)
บางชิปอ้างอิงเสียงลำโพงทั้งหมด (เสียงเธอโดนลบ)
**อ่านจากโค้ดไม่ได้ ต้องลองกับเครื่องจริง**

เคยมีสวิตช์ "ทางที่เสียงเธอวิ่งเข้าสาย" (ช่องเสียงสาย / ช่องเสียงสื่อ) ให้ลองสลับ · **เอาออกแล้ว
(2026-10-31)** เจ้าของ: "ช่องทางเสียงที่ใช้ไม่ได้ มันไม่ได้ยิน ให้เอาออกเลย" · เครื่องจริงใช้ไม่ได้ทั้งสองช่อง
(ดู "เครื่องลบทิ้ง" ข้างล่าง) ทางแก้จริงคือเสียงตรง · ในสายใช้ช่องสายอย่างเดียว · `CallAudio.STREAM_MEDIA`
ที่เหลือเป็นของการคุยในแอป (`MindAudio`) ไม่เกี่ยวกับสาย ห้ามลบ · ทางลำโพงทั้งเส้นยังอยู่เป็นทางสำรอง
เพราะสมองในเครื่อง/พร็อกซี และเครื่องที่ไม่รองรับเสียงตรงยังต้องใช้

### ลำโพงต้องเปิดค้างทั้งสาย (2026-10-06)

เจ้าของ: "ปลายสายหรือคนโทร ไม่ได้ยินเสียงน้องมาย" · ของเดิมสั่งลำโพง**ครั้งเดียว**
ใน `mindAnswer` ซึ่งสายเข้าคือตอน**กริ่งยังดัง** (`answer()` ยังไม่เสร็จ) · หลายเครื่อง
ตั้งเส้นทางใหม่เป็นหูฟังตอนสายต่อติด แล้วไม่มีใครเปิดคืน → เสียงเธอออกหูฟังเบา ๆ
ไมค์ไม่ได้ยิน ไม่มี error อะไรเลย

- `CallAudio.keepSpeaker` เรียกตอนสายที่เธอถือต่อติด (+ เช็กซ้ำ 0.8 / 2.5 วิ) และทุกครั้ง
  ที่ `onCallAudioStateChanged` · ไม่ใช่ลำโพง (หูฟัง/บลูทูธ/หูฟังสาย) = เปิดคืน · ไมค์สาย
  ถูกปิด = เปิดคืน · ไม่เกิน 8 ครั้งต่อสาย · เร่งระดับเสียงซ้ำเมื่อลำโพงติดจริง (ระดับเสียงสาย
  แยกตามอุปกรณ์) · ช่องสื่อเร่งช่องสายด้วย (ระบบกดเสียงสื่อไม่ให้ดังเกินเสียงสายระหว่างสาย)
- เจ้าของ**ปิด**ลำโพงเองบนจอสาย (`CallAudio.ownerRouted`) = ไม่เปิดทับ · แทรกสาย = เลิกเฝ้า
- Dart รอลำโพงติดจริงก่อนคำแรก (`_awaitSpeaker` ไม่เกิน 3 วิ) · ลำโพงปิดเกิน 3 วิระหว่างที่เธอ
  ถือสาย = คำเตือนบนแผงสาย แตะแล้วเปิดคืน (`callSpeakerOn`)
- ไมค์ของทั้งสายไม่ขอ audio focus แล้ว (`audioInterruption: none`)
- รายงาน: `echo` = เสียงเธอดังแค่ไหนในห้องตอนพูด (ไมค์ของเราเอง ไม่ผ่าน AEC ของสาย) ·
  `spkLost` = เคยเห็นลำโพงปิด · **echo ต่ำ** = เสียงไม่ออกลำโพง (เส้นทาง/ระดับเสียง) ·
  **echo สูงแต่ปลายสายไม่ได้ยิน** = AEC ของเครื่องลบทิ้ง → สลับช่องเสียง ·
  เจ้าของเช็กเองได้: เปิดฟังไฟล์บันทึกสาย ถ้าได้ยินเสียงเธอดังชัด แปลว่าลำโพงทำงาน

## ปลายสาย → เธอ — ต้องเปิดบริการการช่วยเหลือพิเศษ (2026-10-06)

ยืนยันจากเอกสาร Android (sharing-audio-input): ระหว่างมีสาย (`MODE_IN_CALL`)
แอปทั่วไปที่อัดเสียงได้**ความเงียบ** · ข้อยกเว้นมีแค่แอประบบที่ถือ
`CAPTURE_AUDIO_OUTPUT` กับ **แอปที่เป็นบริการการช่วยเหลือพิเศษ** · การเป็นแอปโทรศัพท์หลัก
ไม่ช่วย · เจ้าของเจอจริง: "รับแล้ว แต่ไม่ยอมพูดตอบโต้อะไรเลย"

- `MindAccessibility` ไม่อ่านหน้าจอ ไม่กดอะไร · มีไว้ให้ระบบยอมให้อัดระหว่างสาย
- แอปที่ไม่ได้ลงจาก Play ต้อง "อนุญาตการตั้งค่าที่ถูกจำกัด" ก่อน (เหมือนบทบาทแอปโทรศัพท์)
- ไมค์เปิดค้างทั้งสาย (ไม่เปิด-ปิดทุกเทิร์น) · ตอนเธอพูดแค่ไม่ฟัง · ได้เสียงต่อเนื่องไว้บันทึก
- สายที่หูหนวก/ปลายสายไม่ได้ยิน/ไม่ได้ยินใครเลย → `noteIncident` → รายงานส่งเอง
  (`call: rounds heard peak deaf mute a11y stream`)

### ทั้งสองทางเงียบ — จอต้องติดค้าง และรู้ให้ได้ว่าระบบปิดไมค์ (2026-10-07)

เจ้าของ: "คนที่โทรมาไม่ได้ยินเสียงที่มายด์พูดเลย และมายด์ก็ไม่ได้ยินเสียงที่พูดมาเลย ·
เป็นเพราะเปิดลำโพงให้ดังหรือเปล่า"

**ลำโพงไม่ใช่ต้นเหตุ และปิดไม่ได้** — ลำโพงคือทางเดียวที่เสียงวิ่งได้ทั้งสองทาง (เสียงเธอ
ออกลำโพง → ไมค์ของสาย · เสียงคู่สายออกลำโพง → ไมค์ของเธอ) · ปิดลำโพง = เสียงออกหูฟังเบา ๆ
ที่ไมค์ไม่ได้ยินเลยทั้งสองทาง · ความดังสุดก็ไม่ได้ทำให้ไมค์ของเธอได้ยินน้อยลง

กฎจริงจากโค้ด AOSP (`AudioPolicyService::updateUidStates_l`, Android 14) — ระหว่าง
`MODE_IN_CALL` แอปที่เป็นบริการการช่วยเหลือพิเศษอัดได้ **เฉพาะ** แหล่ง `VOICE_RECOGNITION`
**และ** ตอนแอปอยู่สถานะบนสุด · บวกสิทธิ์ไมค์แบบ "ระหว่างใช้งาน" ที่ต้องมีจอของแอปอยู่บนสุดจริง
(บริการที่ระบบโทรศัพท์ผูกไว้ไม่ได้สิทธิ์ไมค์) · ไม่ครบ = ระบบส่งศูนย์ล้วนให้ ไม่มี error

- **จอดับกลางสาย = เธอหูดับ** · ลำโพงเปิดไม่มีอะไรแตะจอ จอดับตามเวลาพักจอ · ของเดิมติดจอ
  ค้างเฉพาะ Android ต่ำกว่า 8.1 → `CallScreen` ติดจอค้าง (decorView `keepScreenOn` ไม่ชน
  ธงของสตูดิโอ) ทั้งจอสายเนทีฟและจอเธอ ตลอดที่ `MindInCallService.mindLive()` · ปล่อยเมื่อ
  สายจบ/เจ้าของแทรกสาย
- **จอสายไม่ขอปลดล็อกแล้ว** (`requestDismissKeyguard`) · เครื่องล็อกด้วย PIN แป้นกรอกรหัส
  เด้งบังจอสายตั้งแต่กริ่งดัง จอที่ถูกบังไม่นับเป็นจอที่ขอติดค้าง แล้วหมดเวลาจอดับ ·
  ขึ้นทับจอล็อก (`setShowWhenLocked`) พอสำหรับรับ/วางสาย
- **รู้ได้ตรง ๆ ว่าระบบปิดไมค์** · `CallAudio.micSilenced` ถาม
  `AudioRecordingConfiguration.isClientSilenced` (Android 10+) ของการอัดแบบ
  `VOICE_RECOGNITION` 16 kHz ส่งมากับ `callInfo` ทุกวินาที → `CallSession.micBlocked`
  (เกินสองวิ) → แผงสายเตือน "ระบบของเครื่องกำลังปิดไมค์ของเธอ" แทนคำเดาว่าหูหนวก ·
  รายงานได้ `silenced=` · ไม่ตั้ง `deaf` ให้ (ปิดชั่วคราวต้องฟังต่อได้เอง)

อ่านรายงานสายครั้งถัดไป:

| `silenced` | `peak` | `echo` | แปลว่า |
|---|---|---|---|
| true | ~0 | ~0 | ระบบปิดไมค์ของเธอ · ดู a11y และจอดับ/สลับแอประหว่างสาย |
| false | ~0 | ~0 | ROM ส่งศูนย์เองโดยไม่ผ่านกฎข้างบน · เครื่องนี้ไม่ให้ฟังสาย |

  และส่งบทที่คุยไปแล้ว 12 บรรทัดล่าสุดให้ในฐานะบันทึก ไม่ใช่คำสั่ง (ไม่งั้นเธอถามชื่อคนโทรซ้ำ) ·
  ตัวกรองเนื้อหาตัดประโยคเดียว เซสชันยังอยู่ จดรหัสไว้เฉย ๆ · ทั้งคู่ล้มจนตกไปทางลำโพง =
  เปิดทางลำโพงและไมค์ต่อ ไม่ตีความว่าตัวช่วยเสียงตรงหลุดเป็นลำโพงเสีย · ยังต้องทดสอบกับสายจริงว่า
  AEC ของเครื่องนี้ยอมให้เสียงจากลำโพงเข้าไมค์หรือไม่
- **ไม่เก็บเสียงคู่สายที่ OpenAI:** `store: false` อยู่ระดับเซสชัน (ค่าตั้งต้นก็ false แต่ระบุไว้) · ใส่ใน
  `delegation.responses` ไม่ได้ · log ลงแค่รหัสข้อผิดพลาด เพราะข้อความอาจมีคีย์แบบบังบางส่วนหรือเนื้อหาในสาย

  ไม่รู้จัก = `marin` · ราคาราว $0.05 ต่อนาที · ไม่มีเซิร์ฟเวอร์จริงในเทสต์ ทุกเหตุการณ์ยึดตามเอกสาร

## คุยสด — OpenAI Realtime (2026-10-06)

สมอง OpenAI ด้วยคีย์ของเจ้าของ + สวิตช์ "คุยสดแบบ Realtime" (เปิดเป็นค่าตั้งต้น) →
`realtime_call.dart`: WebSocket `wss://api.openai.com/v1/realtime?model=gpt-realtime-2.1`
· ไมค์ 16 kHz แปลงเป็น 24 kHz ส่งต่อเนื่อง · เซิร์ฟเวอร์จับจังหวะพูด (server_vad 600 ms)
แล้วตอบเป็นเสียง PCM 24 kHz ทีละชิ้น → `CallAudio.liveStart/liveWrite` (AudioTrack สตรีม)
· บทของทั้งสองฝั่งมาจากการถอดเสียงของเซสชันเอง → บันทึกสาย

- **พูดทีละฝั่ง:** ไมค์ไม่เข้าเซสชันตอนเสียงเธอยังออกลำโพง (+250 ms) · ลำโพง/ไมค์เดียวกัน
  ไม่กั้น = เธอได้ยินตัวเองแล้วตอบตัวเอง · คู่สายแทรกกลางประโยคเธอไม่ได้
- ปากบนเวทีอ่านระดับเสียง PCM ทีละ 20 ms แล้วจับตำแหน่งกับคิวเสียงที่ยังไม่ออกลำโพง
  (`liveAudioPending` หรือคิวตัวช่วยเสียงตรง) · ขยับเฉพาะตอนเสียงเธอกำลังเล่น
  โหมดพึมพำเป็นทางสำรองเฉพาะเมื่อเวทีรับระดับเสียงไม่ได้ · ยังไม่ได้วัดความคลาดเคลื่อนบนเครื่องจริง
  เมื่อเสียงถูกตัดหรือเปลี่ยนจากทางตรงเป็นลำโพง จะล้างคลื่นที่รออยู่ก่อน เพื่อไม่ให้ปากขยับตามเสียงที่ไม่ได้เล่น
- จอเวที: ตอนกริ่งดังแสดงอารมณ์รับรู้สาย; เมื่อรับแล้วจึงเปลี่ยนเป็นคลิปถือโทรศัพท์
  งานแชทที่จบทีหลังไม่เปลี่ยนท่าถือสายทับ · ยังไม่ได้ดูภาพขณะรับสายบนเครื่องจริง
- ต่อไม่ได้ = ทางเดิมตั้งแต่ทัก · หลุดกลางสาย = ทางเดิมต่อ (ไม่ทักซ้ำ)

### เธอหลุดไปพูดอังกฤษ · ไม่ตอบคำถามคนโทร (อ่านจากสายจริง 2026-10-30)

สำเนา `mind.db` ในโฟลเดอร์ GigGok ของเครื่อง vivo (ตาราง `call_notes`) · สายคืน 2026-10-07:
คู่สายพูดไทยล้วน ("ครับ" "อืม" "ฮัลโหล") เธอตอบ "Okay, may I have your name, please?" ต่อกันห้าตา ·
เขาถาม "ที่นี่บริษัทอะไร" และถามหาคนด้วยชื่อ เธอไม่ตอบ วนถามชื่อเขาซ้ำ · ชื่อที่ถอดได้เป็นคำไม่มีความหมาย

- กฎภาษา (`MindPersona.phoneStyle`): สลับเฉพาะเมื่อได้ยินภาษาอื่น**เป็นประโยคชัด ๆ** · คำเดียว คำทับศัพท์
  (ฮัลโหล โอเค) เสียงไม่ชัด ความเงียบ = ไม่สลับ · ไม่แน่ใจ = ภาษาเดิมแล้วขอให้พูดอีกครั้ง
- ตอบคำถามของคนโทรก่อน · คำถามเดียวกันไม่เกินสองครั้ง · ไม่ได้ชื่อก็รับฝากได้ · ถามหาคนด้วยชื่อ =
  เจ้าของไม่สะดวกรับสาย (ไม่ยืนยันว่าเบอร์ของใคร)
- ตัวกันหลุด (`RealtimeCall._holdLanguage`): บทคู่สายเป็นอักษรไทยล้วน แต่บทของเธอเป็นอักษรอังกฤษเป็นหลัก
  → ส่งข้อความระบบเข้าเซสชันว่าคู่สายพูดไทย · ตาที่พูดไปแล้วแก้ไม่ได้ ตาถัดไปกลับมา · ครั้งเดียวต่อตา
  ไม่เกินสามครั้งต่อสาย (คนโทรภาษาอื่นจริงอาจถูกถอดเป็นอักษรไทย) · รายงานสายได้ `rtLang=` และส่งเป็นเหตุการณ์
- ตัวถอดเสียงคู่สายได้ `prompt` (`MindPersona.callTranscriptionHint`): สายไทยมีคำทับศัพท์ + คำทักของสาย
  (ชื่อร้าน/บริษัทที่เจ้าของตั้ง) · มีผลกับบทที่ลงบันทึก/สรุปสาย ไม่ใช่สิ่งที่โมเดลได้ยิน

## ปลายสาย → เธอ (กลไก)

```
เสียงคู่สายออกลำโพง → ไมค์ → AudioRecord (voiceRecognition) → VAD → whisper-1 → ข้อความ
```

หลายเครื่อง **คืนความเงียบสนิท** ให้แอปที่อัดเสียงระหว่างมีสาย
โดยไม่มี error ไม่มี permission denied — ได้ก้อนข้อมูลครบ ขนาดถูกต้อง
แต่ทุกตัวอย่างเป็นศูนย์

จับได้ทางเดียวคือ **วัดระดับเสียงที่อัดได้จริง** ซึ่งเป็นสิ่งที่
`CallSession.micLevel` ทำ และหน้าจอสายแสดงเป็นแถบเล็ก ๆ ข้างสถานะ
เงียบสนิทติดกันสามรอบ → `deaf = true` → เลิกอัด เลิกจ่ายค่าถอดเสียง
แล้วบอกเจ้าของตรง ๆ ว่าเครื่องนี้ไม่ให้ฟัง

**เมื่อหูหนวก ฟีเจอร์ยังทำงานได้ครึ่งหนึ่ง** — ช่องพิมพ์บนหน้าจอสาย
ส่งข้อความให้เธอพูดเข้าสายได้ตามปกติ เพราะทางนั้นไม่ต้องใช้ไมค์เลย

## ทางที่ไม่ต้องลุ้นเลย — รับสายฝั่งเซิร์ฟเวอร์

```
คนโทรเข้า → เบอร์ Twilio/VoIP → เซิร์ฟเวอร์เรา ↔ OpenAI Realtime
                                        ↓
                                   แอปแสดง transcript สด + แทรกสายได้
```

- **หน้าจอสายที่ทำไว้แล้วใช้ต่อได้ทั้งหมด** เปลี่ยนแค่ว่าเสียงวิ่งทางไหน
- คุณภาพเสียงดีกว่ามาก เพราะเป็นสายเสียงตรง ไม่ผ่านอากาศ
- ดีเลย์ต่ำกว่า เพราะไม่ต้องรอ TTS แล้วค่อยเล่น
- ไม่มีเรื่อง AEC ไม่มีเรื่องเครื่องไม่ให้อัด — ไม่ขึ้นกับรุ่นเครื่องเลย

ข้อแลกเปลี่ยน: มีค่าเบอร์รายเดือน + ค่านาที และต้องตั้ง forward สายจากเบอร์เดิม
ไปเบอร์ใหม่ (หรือประกาศเบอร์ใหม่ให้คนที่จะโทรหา)

  `OutgoingRules.noAsking` ที่จับ "ห้ามถามฉัน / อย่าโทรมาถามฉัน / ฉันไม่ว่าง / don't ask me" · ปิด = ไม่มีเครื่องมือเลย) ·
  สวิตช์เดียวกันบนจอสาย หรือปุ่ม "ไม่ว่าง ให้เธอจัดการเอง" · จอดับ/ล็อกตอนเธอจะถาม (`ownerPresent`) ·
  ไม่ตอบใน 45 วิ · ไม่อยู่แล้ว = `ask_owner` ตอบทันทีด้วย `ownerAwayNote` ไม่พักสาย ไม่ถามซ้ำทั้งสาย
- **ไหวพริบ** (`outgoingBlock` ก้อน "ไหวพริบเมื่อเจ้าของตอบเองไม่ได้"): ไม่หยุดคุย · เก็บตัวเลือก ราคา เงื่อนไข
  ข้อเสนอใช้ได้ถึงเมื่อไหร่ · ขอให้กันไว้ก่อนแบบไม่ผูกมัด · ตอบรับแบบมีเงื่อนไข · นัดเวลาติดต่อกลับ · ถูกเร่ง =
  สุภาพแต่หนักแน่น · เลี่ยงเรื่องส่วนตัวเจ้าของ · อ่านอารมณ์ปลายสาย · ทวนก่อนวาง
- **บุคลิกแยกจากสายเข้า** (`MindPersona.outgoingManner`) · ไม่ใช้ค่าความขี้เล่น/จีบที่ตั้งให้คนโทรเข้า ·
  เวลาก่อนเริ่มปิดบทอย่างน้อย 6 นาที (`MindState.outgoingWrapMinutes`) และสะกิดให้วางอีก 3 นาทีหลังจากนั้น
- **รับข้อมูลแล้วทวน** ตกลงแทนได้เฉพาะในขอบเขตที่สั่ง · รายงานหลังสายรวม "ข้อมูลที่ปลายสายให้มา"
  และเรื่องที่รับปากว่าจะติดต่อกลับ (`outgoingSummaryPrompt`)

ยังไม่ได้วัด: ยังไม่มีสายโทรออกจริงสักสาย · GPT-Live ยังไม่รู้ว่าระหว่างรอผลเครื่องมือนาน ๆ
ยังพูดต่อได้ไหม (Realtime ได้ตามโปรโตคอล แต่ยังไม่ได้ลองกับสายจริงเหมือนกัน) · ทางเดิม (ไม่ใช่ OpenAI) ไม่มี `ask_owner` ·
`setMuted` ระหว่างพักบน vivo ยังไม่ได้ฟังจากฝั่งปลายสายจริง (หน่วงกี่มิลลิวินาที คำแรกของเธอขาดไหม ·
ทางตรงตัดเสียงที่ใส่เข้าสายด้วยไหม)

## ไม่มีเน็ต / ใช้เน็ตมือถือ (ตรวจในโค้ด 2026-10-31 · ยังไม่ได้ลองบนเครื่อง)

- **ไม่มีด่านเช็กเน็ตเลยมาก่อน** · สายเข้าตอนไม่มีเน็ตกับสมองที่ต้องใช้เน็ต (หลังบ้าน / คีย์ OpenAI):
  รับสาย → คุยสดต่อไม่ได้ (รอได้ถึง 10 วิ, GPT-Live อีก ~14 วิ) → ทางเดิมทักด้วยคำทักตายตัว → ถอดเสียงล้ม →
  `_markDeaf` เขียนทับข้อความว่า "เปิดการช่วยเหลือพิเศษ" (ผิดเรื่อง) → **เงียบทั้งสาย ไม่วาง ไม่ส่งคืนเจ้าของ** ·
  สายโทรออกตอนไม่มีเน็ตยิ่งแย่: ไม่มีคำทักตายตัว เปิดบทด้วยสมอง → ล้ม → ไม่พูดสักคำ
- **แก้แล้ว (ยังไม่ได้ลองบนเครื่อง):**
  - ตอนกริ่งดัง `InCallActivity.armAutoAnswer`: สมองต้องใช้เน็ต (`MindPrefs.brainNeedsInternet`) แต่ไม่มีเครือข่ายที่
    ระบบตรวจแล้วว่าออกเน็ตได้ (`NET_CAPABILITY_VALIDATED`) = ไม่รับเอง ปล่อยกริ่งดังให้เจ้าของ (`no_internet`) ·
    สมองในเครื่องและเซิร์ฟเวอร์ในบ้านไม่โดนด่านนี้
  - กลางสาย: ล้มเพราะส่งไม่ถึง (`OpenAiFailure.offline`) ≠ หูหนวก · เธอพูด "ขออภัยค่ะ สัญญาณทางนี้ขัดข้อง
    เดี๋ยว…ติดต่อกลับ" ด้วยเสียงในเครื่องแล้ววางสาย (`CallSession._netGoodbye`) · บันทึกสายยังจดให้เจ้าของ
- **ทำงานได้โดยไม่มีเน็ต:** สมองในเครื่อง (Gemma) + ถอดเสียงในเครื่อง (Android 13+ และต้องมีชุดภาษา) + เสียงในเครื่อง ·
  แจ้งเตือนเรื่องด่วนถึงเจ้าของ (แจ้งเตือนในเครื่อง) · ตัวช่วยเสียงตรงที่รันอยู่แล้ว (คุยผ่าน loopback) ·
  แต่คุยสด/เสียงตรง/ask_owner ต้องใช้ OpenAI จึงไม่มีในโหมดนี้ · ยังไม่รู้ว่าเสียงไทยในเครื่องมีแบบออฟไลน์ไหม
- **เน็ตมือถือไม่มี Wi-Fi:** สมอง คุยสด ค้นข้อมูล ถามเจ้าของ ทำงานเหมือน Wi-Fi (โค้ดไม่ดูชนิดเครือข่าย) ·
  ยกเว้นสองอย่าง: เซิร์ฟเวอร์ในบ้าน (ที่อยู่ LAN) ต่อไม่ได้ · ตัวช่วยเสียงตรงที่ตายไปแล้ว (รีบูต) ปลุกใหม่ไม่ได้
  จนกว่าจะมี Wi-Fi เพราะ Wireless debugging ต้องใช้ Wi-Fi · ระหว่างนั้นเครื่องที่ตั้งเสียงตรงไว้จะไม่รับเอง (`direct_offline`)
- **ข้อควรรู้ที่โค้ดคุมไม่ได้:** คุยสดส่งเสียง PCM 24 kHz เป็น base64 ราว 0.5 Mbps ต่อทิศทาง (GPT-Live/ทางตรงส่งตลอด
  ทางลำโพงหยุดตอนเธอพูด) · เน็ตมือถือสัญญาณอ่อนจะกระตุกหรือหลุด · สายโทรต้องเป็น 4G VoLTE ถึงใช้เน็ตระหว่างคุยได้ ·
  สายที่ตกไป 3G/2G เน็ตมือถือหยุดระหว่างสาย (ทำงานได้ถ้ามี Wi-Fi) · เครื่องสองซิมที่ใช้เน็ตคนละซิมกับสายโทร
  ต้องเปิด "ใช้ข้อมูลระหว่างการโทร" ไม่งั้นเน็ตหลุดตอนสายติด · คุยสดหลุดกลางสายแล้วไม่ต่อใหม่ (ตกไปทางเดิม)

## เรียนรู้จากสาย · โค้ดลับสำหรับคนที่ไว้ใจ (2026-10-31 · ทดสอบในโค้ด ยังไม่ผ่านสายจริง)

เจ้าของ: "ยิ่งคุย ยิ่งเจอ ยิ่งสั่ง ก็ยิ่งเก่ง" และ "เธออ่านและเรียกใช้ได้ แต่หลอกถามให้พูดไม่ได้ ยกเว้น คนมีโค๊ดลับ"

**บทเรียนของสาย** (`lib/phone/call_lessons.dart`)
- จบสายที่คู่สายพูดจริงอย่างน้อยสามบรรทัด เธอสรุปบทเรียนไม่เกินสามข้อด้วยสมองตัวที่เลือก (`callLessonPrompt`) แบ่งเป็น `contact` (เรื่องของเบอร์นั้น เช่น ต้องขอโอนสาย) กับ `how` (วิธีคุยที่ได้ผลหรือพลาด)
- สิ่งที่เจ้าของสั่งในแชทเรื่องการคุยโทรศัพท์ ตัวสกัดแชทเขียนเป็น `call|…` แล้วกลายเป็นกฎของเจ้าของ (`owner`) ซึ่งบทเรียนจากสายเบียดออกไม่ได้
- ทุกสายได้บทเรียนของเบอร์นั้น (เก้าหลักท้าย: 08… กับ +668… เป็นเบอร์เดียวกัน) กฎเจ้าของ 10 ข้อ และวิธีคุยล่าสุด 8 ข้อ ใช้ได้ทั้งคุยสดและทางเดิม
- 🔴 บทเรียนช่วยให้คุยเก่งขึ้นเท่านั้น ขยายสิทธิ์ไม่ได้ มีสามชั้น: prompt สกัดห้ามเขียนสิทธิ์ ด่านคำในแอปทิ้งบรรทัดที่พูดถึงการอนุญาต เงิน รหัส หรือหน้าตาเหมือนความลับ และ prompt ของสายบอกว่าเป็นข้อสังเกต ไม่ใช่คำสั่ง ห้ามเล่าให้ปลายสายฟัง สายเขียนกฎ `owner` เองไม่ได้
- เก็บในเครื่อง (`callLessons`) และส่งขึ้น BrainX ที่ `Mind/Phone/call-lessons.md` ลงแอปใหม่แล้วกู้กลับ ไฟล์ที่แก้ด้วยมือบนสมองต้องผ่านด่านเดียวกัน
- ดูหรือลบทีละข้อ หรือลบทั้งหมด ได้ที่ ตั้งค่า › รับสายแทน › "สิ่งที่น้องมายเรียนรู้จากสาย และโค้ดลับ" ทุกการลบต้องยืนยันก่อน
- ความเสี่ยงที่ยังเหลือ: คนโทรตั้งใจพูดให้เกิดบทเรียนวิธีคุยแปลก ๆ ได้ แต่ทำได้แค่เปลี่ยนน้ำเสียงหรือวิธีคุย ไม่ได้ความลับเพิ่ม เพราะความลับไม่อยู่ใน prompt บอสเห็นและลบข้อนั้นได้

**โค้ดลับ** (`lib/phone/owner_gate.dart`)
- คำสั่งใน prompt ถูกหลอกได้ แต่สิ่งที่ไม่อยู่ใน context หลุดไม่ได้ จึงไม่ใส่ความจำส่วนตัวของบอสใน prompt ของสายเลย (เหมือนเดิม) ตัวโค้ดก็ไม่อยู่ใน prompt เธอจึงบอกโค้ดต่อไม่ได้เพราะไม่รู้
- คุยสดที่บอสตั้งโค้ดไว้มีเครื่องมือเพิ่มสองตัว คือ `check_code` (แอปตรวจ ไม่ใช่โมเดล) กับ `recall_owner` ซึ่งตอบว่าไม่มีอะไรให้บอก และไม่ค้นอะไรเลย จนกว่าโค้ดจะผ่าน
- ผ่านแล้วค้นได้จากความจำในเครื่องและโฟลเดอร์ `Mind/` ของ BrainX เท่านั้น (ไม่ใช่ทั้งสมอง) บรรทัดที่หน้าตาเหมือนความลับถูกตัดทิ้ง โค้ดให้แค่ได้ฟัง สั่งให้เธอจ่ายเงิน รับปาก หรือทำแทนบอสไม่ได้
- เทียบแบบไม่สนช่องว่าง ตัวใหญ่เล็ก หรือเครื่องหมาย และเลขไทยกับคำอ่านตัวเลข ("สี่สอง") นับเป็นเลข โค้ดต้องยาวอย่างน้อย 6 ตัวหลังตัดช่องว่าง
- ลองได้สามครั้งต่อสาย ตัวนับอยู่กับสาย ไม่ใช่เซสชัน เปลี่ยนจาก GPT-Live ไป Realtime จึงไม่ได้สิทธิ์ลองใหม่ ผิดห้าครั้งใน 24 ชั่วโมงจะปิดการตรวจทุกสาย จนพ้นเวลาหรือบอสตั้งโค้ดใหม่ บอสได้แจ้งเตือนเมื่อมีคนบอกถูก และเมื่อมีคนลองผิดจนหมดสิทธิ์
- โค้ดที่คนโทรพูดถูกลบจากบทสนทนาก่อนเก็บบันทึก สรุป สรุปบทเรียน และส่งบทให้เซสชันใหม่กลางสาย และถูกลบจากรายงานดีบัค แต่**ไฟล์เสียงที่อัดไว้ยังมีเสียงโค้ดอยู่** และเสียงในสายผ่าน OpenAI เหมือนทุกคำในสาย
- ทางเดิม (ฟัง → ถอด → คิด → พูด) ไม่มีเครื่องมือ จึงไม่มีโค้ดลับ ได้แค่บทเรียน

**คำถามยืนยันตัวตน · สั่งให้เธอใช้เครื่องจากในสาย** (`lib/phone/identity_gate.dart`, `lib/phone/call_phone.dart` · 2026-10-31 · ทดสอบในโค้ด ยังไม่ผ่านสายจริง)

เจ้าของ: "ให้ยืนยันด้วยคำถาม ยืนยันตัวตน อย่างน้อย 3 ข้อ เพื่อเข้าถึงสิทธิ์ เรากำหนดได้ในแอพว่าต้องตอบอะไร"
- บอสตั้งคำถามกับคำตอบเองที่ ตั้งค่า › รับสายแทน › "คำถามยืนยันตัวตน" อย่างน้อย 3 ข้อ ไม่เกิน 10 ข้อ เลือกได้ว่าสายหนึ่งถามกี่ข้อ (3 ถึงจำนวนที่ตั้ง) คำตอบต้องยาวอย่างน้อย 2 ตัวหลังตัดช่องว่าง ห้ามคำถามซ้ำ และห้ามมีคำตอบข้อไหนอยู่ในตัวคำถาม (คนโทรได้ยินคำถาม) เก็บใน Keystore (`SecretStore.kCallQuestions`) ไม่ใช่ค่าตั้งค่าธรรมดา
- **ตรวจในแอป ไม่ใช่ที่โมเดล** คำตอบไม่เคยอยู่ใน prompt หรือในผลเครื่องมือ เธอได้แค่คำถามทีละข้อจาก `identity_question` แล้วส่งคำที่คนโทรตอบเข้า `identity_answer` แอปสุ่มคำถาม ถามครบทุกข้อก่อนค่อยบอกผล ไม่บอกว่าข้อไหนผิดหรือใกล้ถูก ผิดข้อเดียวก็ไม่ผ่าน
- เทียบแบบเดียวกับโค้ดลับ (ไม่สนช่องว่าง ตัวใหญ่เล็ก เครื่องหมาย เลขไทย/คำอ่านตัวเลข) แต่ยอมให้มีคำติดมาน้อยกว่า (คำตอบสั้นยอมได้ 4 ตัว ยาวสุด 12) กันคนพูดคำเดาหลายคำทีเดียว
- หนึ่งครั้งต่อสาย ตัวนับอยู่กับสาย (GPT-Live → Realtime ไม่ได้สิทธิ์ใหม่) ไม่ผ่าน 3 ครั้งใน 24 ชั่วโมง (`callIdentityFails`) ปิดการถามทุกสายจนพ้นเวลาหรือบอสเปลี่ยนคำถาม ผ่านแล้วไม่ล้างตัวนับ เปลี่ยนคำถามกลางสาย = ชุดเก่าใช้ไม่ได้ทันที บอสได้แจ้งเตือนทุกครั้งที่มีคนผ่าน ไม่ผ่าน หรือโดนล็อก
- ผ่านแล้วได้สองอย่างในสายนั้นเท่านั้น: ฟังความจำเรื่องบอส (เปิด `recall_owner` แบบเดียวกับโค้ด) และถ้าเปิดสวิตช์ใช้เครื่องแทนไว้ สั่งงานในเครื่องได้ด้วย `phone_task` · `phone_task` ตอบว่าไม่ได้จนกว่าจะผ่าน (ตัดสินในโค้ด) งานวิ่งเบื้องหลัง เธอคุยต่อได้ ผลงานและคำขอยืนยันขั้นที่ย้อนกลับไม่ได้ถูกส่งเข้าเซสชันทีหลัง (`VoiceSession.announce`) คนในสายต้องตอบตกลงผ่าน `phone_task_confirm` ภายใน 45 วินาที ไม่งั้นไม่ทำ ถามสถานะ/สั่งหยุดได้เฉพาะงานที่สั่งจากสายนั้น สายจบ = หยุดงานที่ยังทำอยู่
- ผ่านแล้วก็สั่งให้จ่ายเงิน โอนเงิน ซื้อของ หรือบอกรหัสผ่าน/OTP ไม่ได้ แอปธนาคารและแอปจ่ายเงินห้ามแตะเสมอ (prompt บอก และฝั่ง Android กันเองด้วย ดูหัวข้อ "ใช้เครื่องแทนเจ้าของจากแชท" ด้านล่าง)
- คำตอบที่คนโทรพูดถูกลบจากบทสนทนา (`[answer]`) ก่อนเก็บบันทึก สรุป ส่งบทให้เซสชันใหม่ และจากผลค้นความจำเรื่องบอส และถูกส่งให้ตัวลบของรายงานดีบัค (ตัวลบข้ามค่าที่สั้นกว่า 8 ตัว แต่คำตอบไม่เคยลง log) **ไฟล์เสียงที่อัดไว้ยังมีเสียงคำตอบ** เหมือนโค้ด
- ใช้ได้เฉพาะคุยสด (Realtime / GPT-Live) ทางเดิมไม่มีเครื่องมือ · ความเสี่ยงที่รู้: ตัวถอดเสียงฟังคำตอบสั้น ๆ ภาษาไทยเพี้ยนแล้วไม่ผ่านทั้งที่ตอบถูก (ตั้งคำตอบที่พูดชัด) และคนที่รู้จักบอสดีอาจเดาคำถามง่าย ๆ ได้

**โทรออกแล้วคนอื่นรับ** (`outgoingBlock`): ถามสุภาพว่าคุยกับใคร ขอให้ต่อสาย ถามเวลาที่ติดต่อได้ ขอเบอร์ตรง แล้วฝากเรื่องสั้น ๆ และเล่ารายละเอียดงานเท่าที่จำเป็น เว้นแต่เขาเป็นคนที่ทำเรื่องนั้นแทนได้จริง

## ใช้เครื่องแทนเจ้าของจากแชท · สอนให้ดูหนึ่งรอบ (`lib/hands/`, `android/…/hands/` · 2026-10-31 · ทดสอบในโค้ด ยังไม่ผ่านเครื่องจริง)

เจ้าของ: "ต้องทำให้ มายด์ คอนโทรลเครื่องได้หมด เปิดได้ได้ทุกแอพ ทำแทนเราได้" · เลือกไว้: ค. ทั้งสั่งด้วยคำพูดและสอนให้ดู · ก. ถามก่อนทำสิ่งที่ย้อนกลับไม่ได้ · ข. คนโทรเข้าสั่งได้ถ้ายืนยันตัวตนผ่าน (ส่วนนั้นอยู่ด้านบน)

**สั่งด้วยคำพูด** (`PhoneAgent`)
- สั่งในแชท เช่น "เปิด LINE ส่งหาแม่ว่าถึงบ้านแล้ว" เธอเขียนแท็ก `[[ทำในเครื่อง: …]]` แอปตัดแท็กออกก่อนขึ้นจอ/ก่อนพูด แล้วเริ่มงาน
- ทุกขั้น: อ่านจอเป็นตัวหนังสือ (ไม่ใช่ภาพ) → ถามสมองตัวที่เลือกแบบไม่มีบทเก่า → ทำหนึ่งขั้น → อ่านจอใหม่ · ใช้ได้ทุกสมองรวมถึงสมองในเครื่อง ใช้เพดานงานเบื้องหลัง (`ReplyCap.background`)
- ทำได้: กด กดค้าง พิมพ์ กด Enter เลื่อน ย้อนกลับ หน้าหลัก แอปล่าสุด แถบแจ้งเตือน เปิดแอปตามชื่อ ตั้งปลุก เปิดหน้าเพิ่มนัดในปฏิทิน เปิดร่างอีเมล
- ไม่เกิน 30 ขั้นต่องาน · ทำขั้นเดิมบนจอเดิม 4 ครั้ง = ติด หยุดเอง · อ่านจอไม่ได้ 3 ครั้งติด = หยุด · สมองตอบไม่เป็น JSON ถามซ้ำหนึ่งครั้ง
- ทีละงาน: กดซ้ำ สั่งซ้อนจากแชทกับสาย หรือสั่งระหว่างกำลังสอน = ตอบว่าเครื่องไม่ว่าง ไม่เริ่มตัวที่สอง
- ผลบอกในแชท และถ้าแอปไม่ได้อยู่บนจอ บอกทางแจ้งเตือนด้วย
- ปิดสวิตช์ ตั้งค่า › ทั่วไป › "ใช้เครื่องแทน" = ไม่สอนแท็ก ไม่มีเครื่องมือในสาย และหยุดงานที่ทำอยู่

**สอนให้ดูหนึ่งรอบ** (`PhoneMacro`, `HandsRecorder.kt`)
- ตั้งค่า › ทั่วไป › ใช้เครื่องแทน › สอน → ตั้งชื่อ → บอสทำให้ดูหนึ่งรอบ → กดจบ · จำแอปที่เปิด ปุ่มที่กด (ตามคำบนปุ่ม ไม่ใช่ตำแหน่ง) ข้อความที่พิมพ์ และการเลื่อน · ช่องรหัสผ่านไม่จำ
- สั่งด้วยชื่อในแชท หรือกด "ทำ" ในตั้งค่า · หาปุ่มเดิมไม่เจอ (แอปเปลี่ยนหน้าตา) = ไม่กดมั่ว ส่งขั้นที่เหลือให้สมองอ่านจอทำต่อเอง

**ถามก่อนขั้นที่ย้อนกลับไม่ได้** (`PhonePolicy`)
- 🔴 ตัดสินด้วยโค้ด ไม่ใช่ prompt: ดูคำบนปุ่มที่จะกดจริง (ส่ง จ่าย ซื้อ ลบ โอน โพสต์ โทร ติดตั้ง ฯลฯ ไทยและอังกฤษ) · ปุ่มตกลง/ยืนยันบนจอที่มีคำพวกนั้น · Enter ในช่องที่ไม่ใช่ช่องค้นหา (ในแชทคือส่ง) · สวิตช์ในหน้าตั้งค่าเครื่อง · และขั้นที่สมองติดธง `risky` เอง
- ถามในแอปหรือปุ่มในแจ้งเตือน ทางไหนมาก่อนใช้ทางนั้น · ไม่ตอบใน 2 นาที = ไม่ทำและหยุดงาน · ปุ่ม **หยุด** อยู่ทั้งในแจ้งเตือนและในแอป Android ปฏิเสธทุกคำสั่งต่อจากนั้นเอง
- ข้อจำกัด: ปุ่มที่เป็นไอคอนล้วน ไม่มีคำหรือคำอธิบายเลย โค้ดจับไม่ได้ เหลือแค่ธง `risky` ของสมอง

**กันแอปธนาคาร · ตัดสินที่ Android** (`HandsPolicy.kt`, `HandsSwitch.kt`)
- บริการช่วยเหลือพิเศษตัวใหม่ (`MindHands`) แยกจากตัวฟังเสียงสาย · ถ้ามีสิทธิ์ `WRITE_SECURE_SETTINGS` (จากการตั้งค่าเสียงตรง) แอปเปิดเองตอนเริ่มงาน แล้วปิดเองเมื่อว่าง 60 วินาที · เติม/ลบเฉพาะชื่อบริการของเรา ไม่แตะบริการอื่น · บอสเปิดเองในตั้งค่า = ไม่ไปปิดให้ · ไม่มีสิทธิ์นั้น = บอสต้องเปิดเองในหน้าตั้งค่าการช่วยเหลือพิเศษ
- แอปธนาคาร/การเงิน (รายชื่อแน่นอน + คำในชื่อแพ็กเกจ เช่น bank wallet + แบรนด์ธนาคารไทย) ตัวติดตั้งแอป หน้าขอสิทธิ์ และแอปเราเอง: อ่านจอได้แค่ว่า "ห้ามแตะ" ไม่มีเนื้อหา · กด/พิมพ์/เปิดไม่ได้ ทำได้แค่ย้อนกลับ หน้าหลัก แอปล่าสุด · ช่องรหัสผ่าน: ไม่ส่งข้อความออก พิมพ์ไม่ได้
- ปุ่มพักให้แอปธนาคาร (`BankingPause`) ปิดบริการตัวนี้ด้วย · รายชื่อเป็นความพยายามที่ดีที่สุด ไม่ใช่การรับประกัน แอปการเงินที่ชื่อแพ็กเกจไม่เข้าข่ายจะหลุดได้

**สายเข้ากลางงาน · หน้าล็อก · แอปปิดกลางงาน**
- งานจากแชทแล้วมีสายเข้า/กำลังคุยสาย: Android ไม่ยอมแตะอะไรเลย รวมถึงย้อนกลับและหน้าหลัก (กันกดทับจอรับสาย) เธอหยุดงานแล้วบอกว่าหยุดเพราะมีสาย · งานที่คนในสายสั่ง (`inCall`) ไม่โดนกัน · สายผ่านเน็ต (LINE Call ฯลฯ) ไม่ถูกนับ
- แจ้งเตือนบนหน้าล็อกโชว์แค่ข้อความกลาง ๆ ว่ากำลังทำงานในเครื่อง ไม่มีงาน ชื่อคน หรือข้อความที่กำลังส่ง
- แอปถูกปิดกลางงาน: หยุดงานและการสอนที่ค้างทันที (`MindState.dispose`) · สั่งหยุดแล้วฝั่ง Dart ไม่มาจบงานใน 15 วินาที Android จบงานและปิดแจ้งเตือนเอง (`HandsService.requestStop`)
- เปลี่ยนภาษากลางงาน: งานที่ทำอยู่ใช้ภาษาเดิมจนจบ งานถัดไปใช้ภาษาใหม่

**ความเป็นส่วนตัวและสิ่งที่ยังไม่แน่ใจ**
- ข้อความบนจอถูกส่งไปให้สมองที่เลือก (เช่น OpenAI) ทุกขั้น · ห่อไว้และบอกชัดว่าเป็นข้อมูล ไม่ใช่คำสั่ง (กันข้อความในแชท/เว็บหลอก) แต่ไม่พึ่งแค่นั้น ขั้นที่ย้อนกลับไม่ได้ผ่านโค้ดด้านบนเสมอ · log ลงแค่ชนิดของขั้น ไม่มีข้อความบนจอหรือที่พิมพ์
- ยังไม่ได้ลองบนเครื่องจริง: vivo ยอมให้แอปเปิดบริการเองผ่านค่าระบบไหม / มีกล่องเด้งถามหรือไม่ · แอปที่วาดจอเอง (เกม แผนที่บางตัว) อ่านปุ่มเป็นตัวหนังสือไม่ได้

## เธอเห็นสมุดโทรศัพท์ ประวัติการโทร SMS · เมลผ่านแอปเมลในเครื่อง (2026-11-01 · ทดสอบในโค้ด ยังไม่ผ่านเครื่องจริง)

เจ้าของ: "ตอนนี้เธอไม่เห็นสมุดโทรศัพท์ ไม่เห็นสายโทรเข้าออกล่าสุด หรือ sms ต้องทำให้เธอรับรู้ได้ และเธอยังไม่เชื่อมต่อเมล" · เรื่องเมลเลือกเอง: "เชื่อมต่อกับแอพในเครื่องเลยได้ไหม เช่น google mail hotmail" · "ทำได้หมด อยากให้คอนโทรลเครื่องแล้วกดเปิดพวกมันขึ้นมาเธอใช้มันได้เลย"

**ก่อนแก้ (อ่านจากโค้ดและเครื่องจริง vivo V2144 · 0.1.50-fix)**
- สิทธิ์สมุดโทรศัพท์ สาย และสถานะโทรศัพท์ได้แล้วบนเครื่อง · ปัญหาไม่ใช่สิทธิ์ แต่เธอไม่ได้หยิบไปใช้: ในแชทเห็นแค่สายของวันนี้ไม่เกิน 6 สาย · สมุดโทรศัพท์ใช้แค่แปลงชื่อเป็นเบอร์ตอนโทรออก (เธอไม่เห็นผล) · SMS ไม่มีโค้ดและไม่มีสิทธิ์ `READ_SMS`
- เมล: "มือ" (`MindHands`) ทำงานได้และเปิดเองตอนเริ่มงาน (`WRITE_SECURE_SETTINGS` ได้แล้ว · `enabled_accessibility_services` เป็น null ตอนว่างคือปกติ) · แต่บทบาทสอนแค่ "เปิดหน้าเขียนอีเมล" · ตัวคุมเครื่องสรุปได้แค่ "1–2 ประโยคว่าทำอะไร" · หน้าเมลเขียนว่ายังไม่ได้เชื่อม · เครื่องมี Gmail ไม่มี Outlook · แอป SMS หลักคือ `com.android.mms`

**สมุดโทรศัพท์ / สาย / SMS** (`lib/phone/phone_lookup.dart`, `PhoneData.kt`)
- แท็กบรรทัดเดียวแบบเดียวกับค้นเว็บ: `[[รายชื่อ: ชื่อหรือเบอร์]]` · `[[ประวัติโทร: ชื่อ เบอร์ ไม่ได้รับ โทรเข้า โทรออก วันนี้ เมื่อวาน]]` · `[[SMS: ชื่อ เบอร์ ผู้ส่ง หรือคำในข้อความ]]` (อังกฤษ `contacts` / `call_log` / `sms`) · แอปอ่านจากเครื่อง แนบผลแล้วให้เธอตอบอีกรอบ (สูงสุด 2 รอบรวมกับค้นเว็บ) · บทที่ขอกับผลไม่ลงบทสนทนา
- ไม่ขึ้นกับสวิตช์ค้นเว็บ · ไม่ยัดรายการทั้งก้อนเข้า system prompt (สมองในเครื่องต้องสร้าง session ใหม่ทุกตา)
- สมุด: ชื่อใช้ `LIKE %คำ%` (ชื่อไทยไม่มีช่องว่าง ตัวกรองของระบบเทียบแค่ต้นคำ) · เบอร์ใช้ตัวกรองของระบบ · ไม่เกิน 15 รายชื่อ + จำนวนรายชื่อทั้งหมด
- สาย: อ่าน 150 สายล่าสุด กรองชนิด/วัน/ชื่อ/เบอร์ (เทียบเลขท้าย 8 หลัก) ฝั่ง Dart · ไม่เกิน 15 บรรทัด มีเวลาคุยและซิม
- SMS: กล่องเข้า + ส่งออก สแกนไม่เกิน 600 แถว · ตัดเนื้อความที่ 400 ตัวอักษรฝั่ง Kotlin และ 240 ตัวอักษรฝั่ง Dart · 🔴 RCS ("แชท" ของ Google Messages) ไม่อยู่ใน `content://sms` เธอเห็นแค่ SMS ธรรมดา
- 🔴 ห้ามต่อ `LIMIT n` ท้าย sortOrder (provider รุ่นใหม่โยน `Invalid token LIMIT`) · นับเองในลูป · อ่าน provider นอกเธรดหลัก (`SystemBridge.offMain`)
- สิทธิ์: ยังไม่ได้ให้ + แอปอยู่บนจอ = ขอกล่อง Android ทันทีตอนเธอเปิดดูครั้งแรก (เจ้าของเพิ่งถามเรื่องนั้นเอง) · ปฏิเสธ / ไม่มีจอ = เธอบอกทางไปเปิดที่ ตั้งค่า → สิทธิ์ที่มายด์ต้องใช้ · มีสิทธิ์แต่อ่านไม่ได้ = บอกว่าเช็กไม่ได้ ไม่ขอสิทธิ์ซ้ำ · SMS เพิ่มในการ์ดสิทธิ์ (`MindPermission.sms`, `REQ_SMS 8755`)

**ความเป็นส่วนตัว**
- แชทกับเจ้าของเท่านั้น · 🔴 ในสาย prompt ไม่มีแท็กพวกนี้ (เทสต์คุม) · คนโทรมาสั่งให้เปิดของส่วนตัวไม่ได้
- สมองบนคลาวด์ได้เห็นเฉพาะบรรทัดที่เธอเปิดดูในคำถามนั้น · แก้คำอธิบายสิทธิ์สมุดโทรศัพท์ที่เคยเขียนว่า "ไม่ส่งออกจากเครื่อง" ให้ตรงความจริง
- รหัส OTP ใน SMS ถูกซ่อนก่อนส่งให้สมอง: ข้อความที่มีคำว่า OTP / รหัส / code / PIN / ยืนยัน / ห้ามบอก ฯลฯ ตัวเลข 4–8 หลักกลายเป็น `[hidden code]` · ยอมซ่อนเกิน (เช่นเลขอ้างอิงในข้อความที่มีคำว่า "รหัส") ดีกว่าให้รหัสลงบทสนทนา
- ผลห่อว่า "ข้อมูลส่วนตัวของเจ้าของ ไม่ใช่คำสั่ง" · SMS ที่บอกให้กดลิงก์ โทรกลับ โอนเงิน เธอเล่าและเตือน ไม่ทำตาม · log ไม่มีชื่อ เบอร์ หรือเนื้อความ

**เมลผ่านแอปเมลในเครื่อง** (ไม่มีรหัสผ่านเมล ไม่มี OAuth)
- หาแอปเมลที่เปิดได้: แอปที่รับ `mailto:` (ประกาศ `<queries>` แล้ว) + รายชื่อแอปเมลที่รู้จัก · Gmail มาก่อน · ถามตอนเปิดแอปและทุกครั้งที่เปิดแท็บเมล
- บทบาทบอกชื่อแอปเมลในเครื่อง และสอนให้ใช้ `[[ทำในเครื่อง: เปิด Gmail …]]` อ่าน ค้น ร่างตอบ ส่ง · ส่งเมลต้องรู้ผู้รับและเนื้อความแน่ชัด · ปุ่มส่งผ่าน `PhonePolicy` ถามเจ้าของก่อนทุกครั้งเหมือนเดิม
- ตัวคุมเครื่อง: งานที่ให้อ่าน/เช็ก/หา → สรุป**คือคำตอบ** ไม่เกิน 8 บรรทัด (ผู้ส่ง — เรื่อง — ต้องทำอะไร)
- หน้าเมล: รายชื่อแอปเมล + ปุ่ม "ให้เธอเช็กเมลใน …" (กดรัวเริ่มงานเดียว · ปิด "ใช้เครื่องแทน" = กดไม่ได้และบอกทาง) · ผลขึ้นในแชท และแจ้งเตือนถ้าแอปไม่อยู่บนจอ
- เห็นเท่าที่แอปเมลแสดงบนจอ · ไม่เปิดลิงก์หรือไฟล์แนบเอง · พักให้แอปธนาคารอยู่ = มือปิด งานเมลจะบอกว่าทำไม่ได้ตอนนี้

**วัดบนเครื่องจริง (vivo V2144 · Android 15 · 0.1.52-phone ติดตั้งด้วย `adb install -r` · 2026-11-01)**
- `READ_SMS` **ได้มาเองโดยไม่มีกล่องเด้ง**: `granted=true` ธง `RESTRICTION_INSTALLER_EXEMPT|RESTRICTION_SYSTEM_EXEMPT|GRANTED_BY_ROLE` · เพราะ GigGok เป็นแอปโทรศัพท์หลัก บทบาทนั้นให้สิทธิ์อ่าน SMS มาด้วย · เครื่องที่ไม่ได้ตั้งเป็นแอปหลักยังต้องกดอนุญาตเอง (ยังไม่ได้วัด)
- หน้าเมลเจอ Gmail และขึ้นปุ่ม "ให้เธอเช็กเมลใน Gmail" · แอปเปิดปกติ ไม่มืด

**ยังไม่ได้วัด**
- เธอตอบเรื่องสาย/SMS/สมุดได้จริงในแชท (ไม่ได้พิมพ์ทดสอบในแชทของบอส — ลงประวัติและใช้โควตาสมอง)
- ปุ่มเช็กเมลบน Gmail จริง: อ่านรายการในกล่องจดหมายเป็นตัวหนังสือได้ครบไหม · สรุปยาวพอไหมกับสมองในเครื่อง
- ติดตั้งจากตัวอัปเดตในแอปบนเครื่องที่ไม่ได้เป็นแอปโทรศัพท์หลัก: `READ_SMS` ถูกอนุญาตโดยตัวติดตั้งไหม (ดูธงด้วย `dumpsys package com.xjanova.videogirl | grep READ_SMS`)
