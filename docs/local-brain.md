# สมองในเครื่อง — ไฟล์โมเดลกับรันไทม์ต้องเป็นคู่เดียวกัน

## ✅ GPU ใช้ไฟล์ปกติตัวเดียวกับ CPU (แก้ความเข้าใจเมื่อ 2026-10-05)

ไฟล์ `gemma-4-E2B-it.litertlm` / `gemma-4-E4B-it.litertlm` (ไม่มีคำต่อท้าย)
คือตัวที่ Google วัดผลบน Android **ทั้ง CPU และ GPU** ตามการ์ดโมเดล:

| S26 Ultra · E2B | อ่าน prompt (โทเค็น/วิ) | พิมพ์คำตอบ (โทเค็น/วิ) | คำแรก (วิ) | แรม CPU (MB) |
|---|---|---|---|---|
| CPU | 557 | 46.9 | 1.8 | 1733 |
| GPU | 3,808 | 52.1 | 0.3 | 676 |

ช้าบนมือถือคือการ**อ่าน prompt** · prompt ของมายด์ยาว (บุคลิก ความจำ
ตารางนัด และบทสนทนาที่เล่าย้อน) GPU จึงช่วยได้มากที่สุดตรงนี้

อ่านหัวไฟล์ซ้ำ (HTTP Range 32 KB แรก) พบว่า `backend_constraint: cpu`
**ผูกอยู่กับส่วนเสียงและภาพเท่านั้น**:

| ส่วน | ป้าย |
|---|---|
| `tf_lite_prefill_decode` (ตัวคิดหลัก) | `prefer_activation_type: fp16` — **ไม่มี** backend_constraint |
| `tf_lite_vision_adapter` · `tf_lite_audio_adapter` · `tf_lite_audio_encoder_hw` | `backend_constraint: cpu` |

บันทึกเดิม (2026-09-03) อ่านป้ายนี้เป็นของทั้งไฟล์ แล้วสรุปผิดว่าไม่มีทาง GPU

### สิ่งที่ต้องมีให้ GPU ทำงาน

- `<uses-native-library>` ของ `libOpenCL.so` / `libOpenCL-car.so` /
  `libOpenCL-pixel.so` / `libvndksupport.so` ใน AndroidManifest · Android 12+
  ไม่ยอมให้แอปเปิดไลบรารีของผู้ผลิตเครื่องที่ไม่ได้ประกาศ
- `LocalBrain` ลอง GPU ก่อน ล้มก็ตกไป CPU ในรอบเดียวกัน และจำไว้ว่าเครื่องนี้
  GPU ใช้ไม่ได้ · ไดรเวอร์ที่พา process ตาย ถูกจับด้วยธง `gemmaGpuTrying`
  ใน SharedPreferences (ค้างอยู่ตอนเปิดรอบหน้า = ตายกลางทาง → ใช้ CPU)
- เปิด GPU ครั้งแรกช้ากว่าปกติ (คอมไพล์ shader) แล้วเร็วขึ้นเพราะมี cache

⚠️ **ยังไม่ได้ลองบนเครื่องจริง** — ทุกข้อข้างบนมาจากการ์ดโมเดล หัวไฟล์ และ
ซอร์สของปลั๊กอิน ต้องดูหน้าตั้งค่าว่าขึ้น "ตอนนี้คิดด้วย GPU" จริงไหม

## 🔴 ไฟล์ `-gpu.litertlm` ใช้บน Android ไม่ได้ — มันคือรุ่น WebGPU

ไฟล์ `-gpu` ขนาด**เท่าไฟล์ `-web` ทุกไบต์** (E2B 2,008,432,640 · E4B
2,969,059,328) คือรุ่นสำหรับเบราว์เซอร์ ไม่ใช่ GPU ของมือถือ

| ไฟล์ | `backend_constraint` | ส่วนข้างใน |
|---|---|---|
| `gemma-4-E2B-it-gpu.litertlm` · `gemma-4-E4B-it-gpu.litertlm` | `gpu_artisan` | `gpu_artisan`, `gpu_artisan_weights_version`, `tf_lite_artisan_text_decoder` |

flutter_gemma 0.13.6 พ่วง `com.google.ai.edge.litertlm:litertlm-android:0.10.0`
ซึ่งรู้จักแต่ทางเดิน `tf_lite_prefill_decode` พอเจอไฟล์ `gpu_artisan` มันจึงตาย
ตอนสร้าง engine:

```
Failed to initialize LiteRT-LM: Failed to create engine:
NOT_FOUND: TF_LITE_PREFILL_DECODE not found in the model.
```

ไฟล์ `-gpu` ถูกสร้าง 2026-08-06 ส่วนไฟล์ CPU สร้าง 2026-04-28 — **รูปแบบใหม่กว่า
รันไทม์ที่เราพ่วงมา** ไม่ใช่ไฟล์เสียและไม่ใช่โหลดไม่ครบ

### ทำไมมันเจ็บกว่าที่ควร

พังตอน**สร้าง engine** ไม่ใช่ตอนโหลด · ลำดับที่ผู้ใช้เจอคือ

1. โหลดจบ 100% เสียเน็ต 3 GB
2. หน้าตั้งค่าขึ้นเขียว "พร้อมใช้แบบออฟไลน์"
3. ทักคำแรก → ได้ชื่อ signature ข้างในไฟล์ขึ้นมาบนจอ

ไม่มีจุดไหนก่อนหน้าที่บอกได้เลยว่าจะพัง และไม่มีเทสต์ในเครื่องไหนจับได้
เพราะไฟล์ไม่ได้อยู่ในเครื่องที่รันเทสต์ ที่ทำได้คือ**กันที่ชื่อไฟล์**
(`test/local_brain_test.dart` · "ห้ามชี้ไปที่ไฟล์ -gpu")

## ปลั๊กอินรุ่นใหม่

`flutter_gemma` ถูกประกาศเลิกพัฒนาแล้ว (1.11.4 คือตัวสุดท้าย) ย้ายไปเป็น
`flutter_edge_ai` · รุ่น 1.x ต้องใช้ Dart 3.12 / Flutter 3.44 ขึ้นไป
(เครื่องนี้และ CI ใช้ Flutter 3.41.7) และ API เปลี่ยนหลายจุด
ข้อดีที่จะได้: LiteRT-LM ใหม่กว่า, speculative decoding (คำตอบเร็วขึ้นอีก
เกือบเท่าตัวบน GPU), แก้ GPU sampler บน Android (0.15.1 / 0.16.3)
· เป็นงานคนละก้อน ต้องขยับ Flutter ทั้งโปรเจกต์ก่อน

## รุ่นที่ถอดออกต้องตามไปลบไฟล์

`retiredModels` ใน [local_brain.dart](../lib/ai/local_brain.dart) มีไว้เพราะ
**ถอดชื่อออกจาก `GemmaVariant` เฉย ๆ ไม่พอ** ทั้งปุ่มลบและการสแกนตอนเปิดแอป
วิ่งบน `GemmaVariant.values` ไฟล์ 3 GB ที่ค้างอยู่จึงกลายเป็นของที่ไม่มีปุ่มไหน
ในแอปลบได้อีกเลย

ปลั๊กอินเก็บไฟล์แยกตาม**ชื่อไฟล์** (`mobile_model_manager` · `spec.files[]
.filename` ซึ่งมาจาก basename ของ URL) ไม่ใช่ชื่อรุ่น ลบตัวที่ถอดออกจึงไม่โดน
ของที่ยังใช้อยู่

## ขนาดไฟล์ (ยืนยันกับ Hugging Face 2026-09-03)

| รุ่น | ไฟล์ | ไบต์ |
|---|---|---|
| E2B | `gemma-4-E2B-it.litertlm` | 2,588,147,712 |
| E4B | `gemma-4-E4B-it.litertlm` | 3,659,530,240 |

ตัวเลขพวกนี้ถูกใช้ตรวจว่าโหลดครบไหม (`isComplete` เผื่อคลาดเคลื่อน 2%)
เพราะ `isModelInstalled()` ของปลั๊กอินดูแค่ว่า**มีไฟล์อยู่** ไฟล์ครึ่งเดียว
จากเน็ตที่หลุดกลางทางจึงตอบว่า "ติดตั้งแล้ว" ตลอดไปและปุ่มโหลดจะหายไป

## ค่าแนะนำเป็น E2B ทุกชั้นแรม

E4B ใหญ่กว่า 1 GB และอ่าน prompt ช้ากว่า E2B ราวสามเท่า (GPU 1,293 เทียบ
3,808 โทเค็น/วิ) · ตั้งเป็นค่าแนะนำสำหรับเครื่องแรม 12 GB เท่ากับยัดของที่ช้า
ใส่มือคนที่เครื่องแรงที่สุดโดยที่เขาไม่ได้ขอ · E4B ยังอยู่ใน `allowed` ให้เลือกเองได้
