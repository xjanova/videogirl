# GigGok backend — สเปกฝั่งเซิร์ฟเวอร์

แอปนี้จะถูก **ขายและให้เช่า** ในอนาคต แปลว่าต้องมี backend ตั้งแต่แรก
ไม่ใช่ค่อยมาเติมทีหลัง เพราะสามอย่างนี้ทำในแอปเดี่ยว ๆ ไม่ได้เลย:

1. **คีย์ผู้ให้บริการต้องไม่อยู่ในเครื่องผู้ใช้** — `--dart-define` ฝังคีย์ลงไบนารีจริง
   ใครโหลด APK ไปแกะก็อ่านได้ (ดู [security.md](security.md))
2. **โควตาและการเช่า** — ต้องนับ ต้องตัด ต้องต่ออายุได้ ทำฝั่งเครื่องผู้ใช้ = โดนโกงแน่
3. **โคลนเสียงต้องใช้ GPU** — โมเดลอย่าง F5-TTS / GPT-SoVITS ยัดลงมือถือไม่ไหว

## ตั้งอยู่ที่ไหน

ต่อยอด **xman studio (Laravel, `xman4289.com`)** ที่มีของพร้อมอยู่แล้ว:
`Setting::setValue` + `Crypt::encryptString` สำหรับเก็บคีย์ และ `AiChatService`
ที่สลับ provider ได้

> ⚠️ **โฮสต์ Laravel รันโมเดลโคลนเสียงเองไม่ได้** — ต้องมี GPU และ Python
> Laravel ควรเป็น **ประตูหน้า** (auth / โควตา / บิล / คิวงาน) แล้วส่งงานหนักต่อไปที่
> GPU worker หรือผู้ให้บริการภายนอกที่ Laravel ถือคีย์ไว้ฝั่งเดียว

```
แอป GigGok ──(bearer ของผู้ใช้)──► Laravel xman4289.com
                                      ├── /chat   → OpenAI (คีย์อยู่ที่นี่)
                                      ├── /tts    → เสียงมาตรฐาน
                                      ├── /voices → คิวโคลนเสียง ──► GPU worker
                                      └── โควตา / แผนการเช่า / บิล
```

## รูปแบบ auth ที่ควรใช้

**อย่าเขียน endpoint ชุดใหม่ทั้งชุด** — บทเรียนจาก `aixman`: แก้ตัว resolve ผู้ใช้
ให้รับได้ทั้ง **Bearer** และ **cookie** ผ่าน helper ตัวเดียว แล้ว endpoint เดิมทั้งหมด
ใช้กับมือถือได้ทันที เพิ่มแค่ `login` / `refresh` / `me`

การเพิกถอนก็ได้ฟรี ถ้าตัว resolve อ่าน `users.is_active` จาก DB ทุก request อยู่แล้ว —
ปิดบัญชีฝั่งเว็บ ตัดมือถือทันที ไม่ต้องมีตาราง token

## API ที่แอปเรียก

ฐาน: `https://xman4289.com/api/giggok/v1`

### สมอง

```
POST /chat
{ "messages":[{"role":"system|user|assistant","content":"…"}], "model":"gpt-5.6-sol" }
→ 200 { "reply":"…", "usage":{…} }
```

ให้ Laravel เป็นคนใส่คีย์ OpenAI · แอปไม่เคยเห็นคีย์
เมื่อ endpoint นี้พร้อม ให้เพิ่ม `BrainProvider.giggok` ในแอปแล้วตั้งเป็นค่าเริ่มต้น
ของ build ที่ปล่อยขาย ส่วน `BrainProvider.openai` เก็บไว้ใช้ตอนพัฒนาเท่านั้น

### เสียง

```
POST /tts
{ "text":"…", "voice_id":"…" }
→ 200 audio/mpeg (ไบต์ล้วน ไม่ใช่ JSON)
```

แอปคาดว่าได้ **ไบต์เสียงตรง ๆ** เพราะต้องส่งเข้า WebView เป็น blob ให้ lipsync
อ่านคลื่นได้ (ดู `lib/avatar/avatar_view.dart`)

### โคลนเสียง

```
POST   /voices          multipart: sample=<wav>, name=<ชื่อ>
→ 201 { "id":"…", "name":"…", "status":"pending|training|ready|failed" }

GET    /voices          → 200 [ {id,name,status,seconds}, … ]
DELETE /voices/{id}     → 204
```

**ข้อกำหนดของตัวอย่างเสียงที่แอปส่งมา** (ดู `lib/ai/voice_clone.dart`):
WAV · 16 บิต · 24 kHz · โมโน · 30–120 วินาที
ห้ามรับไฟล์บีบอัด ร่องรอยการบีบจะติดไปในเสียงที่โคลนออกมา

### รหัสตอบกลับที่แอปแปลเป็นข้อความไทยให้แล้ว

| รหัส | แอปแสดงว่า |
|---|---|
| 401 / 403 | ไม่มีสิทธิ์ใช้บริการนี้ ลองล็อกอินใหม่ |
| 402 | โควตาหมดแล้ว |
| 413 | ไฟล์เสียงใหญ่เกินไป |
| 5xx | เซิร์ฟเวอร์ขัดข้อง ลองใหม่อีกครั้ง |

ถ้าส่ง `{"message":"…"}` มาด้วย แอปจะแสดงข้อความนั้นแทน — เขียนเป็นภาษาคน
อย่าส่ง stack trace หรือ path ของเซิร์ฟเวอร์ออกมา

## เลือกเครื่องโคลนเสียงยังไง

| ทาง | ข้อดี | ข้อเสีย |
|---|---|---|
| **API ภายนอก** (ElevenLabs ฯลฯ) | เริ่มได้เลย ไม่ต้องดูแล GPU คุณภาพไทยดี | ค่าใช้จ่ายต่อเสียง/ต่อนาที ผูกกับเจ้าอื่น |
| **GPU worker ของเราเอง** (F5-TTS / GPT-SoVITS) | ต้นทุนต่อหน่วยถูกกว่ามากเมื่อสเกล ข้อมูลไม่ออกนอกบ้าน | ต้องมี GPU + ดูแลคิว + ปรับจูนภาษาไทยเอง |

**แนะนำสำหรับตอนเปิดขาย:** เริ่มด้วย API ภายนอกหลัง Laravel ก่อน
สัญญา API ที่เขียนไว้ข้างบน**ไม่เปลี่ยน**เมื่อย้ายไป GPU ของตัวเองทีหลัง
แอปจึงไม่ต้องแก้เลย

**เรื่องภาษาไทยต้องทดสอบจริงก่อนเลือก** — โมเดลโคลนเสียงส่วนใหญ่ฝึกด้วย
อังกฤษ/จีนเป็นหลัก และไม่ประกาศรองรับไทยอย่างเป็นทางการ
อย่าเชื่อหน้าโฆษณา ให้อัดเสียงจริงหนึ่งชุดแล้วลองทั้งสองทางก่อนตัดสินใจ

## เรื่องที่ต้องทำก่อนขายจริง

- [ ] `/chat` ทำงาน แล้วย้ายค่าเริ่มต้นของแอปมาที่นี่ (เลิกฝังคีย์ OpenAI ใน APK)
- [ ] โควตาต่อผู้ใช้ + แผนการเช่า + ตัดสิทธิ์เมื่อหมดอายุ
- [ ] **ขอความยินยอมก่อนโคลนเสียง** — เก็บหลักฐานว่าเจ้าของเสียงอนุญาต
      และห้ามอัปโหลดเสียงคนอื่น นี่เป็นทั้งเรื่องกฎหมายและเรื่องความไว้ใจ
- [ ] ลบตัวอย่างเสียงดิบทิ้งหลังฝึกเสร็จ เก็บเฉพาะสิ่งที่จำเป็นต้องใช้
- [ ] จำกัดอัตราการเรียกต่อบัญชี ไม่งั้นบัญชีเดียวยิงรัวจนบิลบาน



## รายงานดีบัค — ใช้ระบบ bug report เดิมของบ้าน

🔴 **ห้ามสร้างปลายทางใหม่** · `POST /api/v1/bug-reports` มีอยู่แล้วและแอปอื่น
ในบ้านใช้อยู่จริง (นับได้ 3,527 รายงานตอนต่อสาย) มาพร้อมหน้าแอดมิน สถิติ
และตัวส่งเข้า GitHub issue · เคยหลงทำ `/api/giggok/debug-report` ขึ้นมาซ้อน
มาแล้วหนึ่งรอบ แล้วถอนทิ้ง

```
POST /api/v1/bug-reports          (เปิดสาธารณะ ไม่ต้องยืนยันตัว)
{ "product_name":"giggok", "report_type":"bug", "title":"…",
  "description":"<รายงานเต็มเป็น JSON ที่คนอ่านได้>",
  "metadata":{…}, "app_version":"0.1.10",
  "os_version":"Android 16 (API 36)", "device_id":"<เลขสุ่มของการติดตั้ง>" }
→ 201 { "success":true, "data":{ "id":3531 } }
```

**`report_type` รับแค่** `bug` · `misclassification` · `feature_request` ·
`crash` · `performance` — ⚠️ **`diagnostic` ถูกปฏิเสธ 422** ทั้งที่ในฐานมี
3,520 แถวใช้ค่านั้น (เข้ามาก่อนหน้าด้วยทางอื่น) · แถวใหม่ล่าสุดที่เป็น
`diagnostic` คือ 2026-08-27 จาก tping — ถ้า tping ยังส่งค่านั้นอยู่
**รายงานของมันกำลังถูกทิ้งเงียบ ๆ** เรื่องนี้เป็นของฝั่งหลังบ้าน ยังไม่ได้แก้

**`device_id` ของแอปนี้เป็นเลขสุ่มของการติดตั้ง ไม่ใช่ hardware hash**
(แอปอื่นในบ้านส่ง hardware hash) เพราะแอปนี้ขายด้วยคำสัญญาที่แคบกว่า

### อ่านรายงานเอง

`GET` เปิดสาธารณะเหมือนกัน จึงอ่านได้ด้วย HTTP เปล่า ๆ ไม่ต้องมี SSH:

```bash
python tool/reports.py          # รายการล่าสุดของ giggok
python tool/reports.py 3531     # อ่านทั้งฉบับ
python tool/reports.py stats    # สถิติรวม
```

⚠️ ต้องส่ง `User-Agent` ปกติ — ตัวตั้งต้นของ `urllib` โดน WAF ตอบ 403
ขณะที่ `curl` ผ่าน
